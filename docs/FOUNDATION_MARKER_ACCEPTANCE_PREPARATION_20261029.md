## 执行器的实际边界

新增 `evaluations/foundation-marker-runner`，复用已有授权、持久账本、CLI 传输、Windows 短长路径保护、嵌套证据协议和固定错误稿 Worker。单独扩展阶段准入及等待流程；旧文件不改。封存包括 214 个共享/运行依赖文件、宿主 Node 和编译器身份，运行时另绑定生成的 CLI shim。每次启动验证候选全部 86 个外层文件，模型边界再次核对核心包、样本和执行器。

执行器可以生成和发起预定修改，但真实模式不能替用户确认表达、重新核验或最终验收。表达确认只写当前报告的真人确认；随后单独点击“重新核验”才允许核验调用，禁止重新生成。每预定稿阶段最多一次确认与重检，仍待确认则结束本轮。最终验收期间禁止模型调用，须看到同一稿件 `completed` 且 `acceptedBy:user`。离线自动点击独立放在只允许 offline 的模块，不能算真人完成。

首尝试起 45 分钟窗口不因等人重置。每个人工等待成功返回前复核时钟和停止状态；过期、未回答不当作批准。输出限定在专用的新运行目录，不能写进安装包、候选、源码或历史封存包。所有预算拒绝、协议错误、未知用量、非计划调用与用户停止均结束整轮；迟到请求也持久记账。

成本按初次生成/核验、人工重检、预定修改分别记录，失败和本地拒绝不丢阶段。独立结果报告绑定样本、执行器、候选及稿件哈希，分别统计计划/已尝试完成率、初稿/最终稿/放行稿幻觉率、硬误拦、人工转交、最终未放行、两类错误放行及每个合格真人验收任务成本。无法裁定、未执行、技术失败和待人工分别列出，不能用技术通过推断质量通过。

## 离线验证与修正

准备期间发现并修复的都是执行器问题：跨截止时间的返回仍可能被接受；迟到请求与失败阶段归因遗漏；输出路径可能污染冻结目录；两处报告分母边界。定向回归已加入。独立审查还要求禁用未封存的可选 WebSocket 原生模块，并记录 Node、编译器及 shim 身份。

实际 EXE 的两次早期失败记录保留：第一场门检后因 Temp 的 native/非 native 路径别名混用，在建立负例 Worker 前停止，3 次替身调用；第二场进入表达待确认后，模拟点击被首次引导遮挡，10 次替身调用。分别恢复与既有 Worker 一致的目录解析、通过已有“暂时跳过”按钮关闭引导后，完整预演通过。没有改题、救稿、放宽证据标准或修改产品。

通过的完整预演完成 7 例、25 次替身请求、3 次启动、3 次模拟表达确认闭环、4 次模拟最终验收。两个固定错误稿保持原文且被阻止验收；修订稿重新核验，冷重启无额外调用。原始请求/响应、应用记录与持久用量逐条对账，未知用量及未结清调用均为 0。离线合成 token 仅用于账本测试，不是价格预测。

最终封存版本完整流程及 5 项故障共 6/6 通过：内层 JSON 错误在第 1 次停止，嵌套证据格式错误在第 5 次停止，未知用量在第 1 次停止且总量保留未知，业务预算拒绝在第 4 次停止，人工等待超时在第 10 次停止且任务仍待确认。共 46 次合成应用尝试，无额外调用或真实模型开销。新执行器单元 18/18 通过；共享模块 94 项中 93 通过、1 项因当前 Windows 无文件 symlink 权限明确跳过。

最终验证证据见 `docs/evidence/foundation-marker-preparation-verification.json`；冻结复核与独立审核见新包 `runner-review.json`。未经后者通过不得启动 live。

业务预算拒绝场的应用记录将本地失败标为 `usageReported:false`，应用 spendMeter 有 1 条未知；执行器能以“准入前拒绝且未分发”证明远端用量为 0。两者是不同观测层，未改写应用账本，也不宣称故障场所有层的用量标记完全相等。未知真实用量场仍保留未知并停止。

建议额度保持 **最多 40 次应用尝试、800,000 input+output tokens 停止阈值**。不继承旧预算、不做 A/B、不启动正式主评测。模型沿用现有订阅 `gpt-6.1-sol / medium`，本轮尚未探测可用性。阈值不是服务端硬封顶，在途请求可能超出；必须如实记录后停止。
