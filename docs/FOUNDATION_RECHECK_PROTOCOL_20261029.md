# 人工确认后重检：离线协议补丁

本次只修复检查身份及防重放。当前安装的基础版保持冻结，新候选未安装；没有新增真实模型调用，也未启动正式主评测。

## 根因与修复

上一轮 F05 修订后的初次核验已经返回过一次有界结论，要求人工确认表达。用户确认有效，但重检的 semanticCheckId 和兼容键仍与旧检查相同，于是旧消费记录在模型调用前拦住了重检。它是检查生命周期的身份冲突，并非需要放宽事实或表达的语义标准。

现在只有事项详情中的明确“重新核验”操作能够建立新身份，且必须同时绑定事项、核验阶段、当前证据基础、完整报告哈希和用户确认记录哈希。消费记录先落盘，执行器随后启动；运行时能力仅在这一条检查链中有效，读取资料与有界结论沿用同一身份。再次进入 generation.call、重复点击、旧确认、重启和结果不确定均不能重新获得这次授权。

保存失败时不分发。已保存授权而启动保存失败时，排队回调被取消，重启仍能看到已消费记录。直接返回结论、不经过有界结论的路径同样保留消费记录。`finished` 仅表示本轮执行已结束，不代表核验通过；是否通过仍由 verification 和 grounding 判定。

旧有界结论记录不删除，旧身份不明的记录仍保守拒绝。正文、要求或来源变化后不能沿用旧表达确认；明确编辑后仍按原有流程重新检查。确认本身不调用模型，核验通过后仍要求手动验收。
