## 三项实际发现与下一步

1. **优先修复回执的时间语义。** 候选历史文件稿明确写“本轮只读核验时”，回读内容与历史哈希相符，独立审稿判为合格。实际观察在 `05:22:44.621Z`，有效期到 `05:23:44.621Z`；核验于 `05:23:26.142Z` 开始，回执当时尚有效；模型返回于 `05:24:04.268Z`，已过期。本地校验在返回时只保留仍有效工具证据，导致两条实际提供且逐字匹配的引文被当作不可用，继而整稿被拦。需要区分“在某时刻观察到的事实”和“现在/交付时仍成立的状态”：前者保留可信观察及精确时点，后者仍要求新鲜核验。不能简单延长 TTL、冻结一切当前状态，或把历史写入当作当前交付。离线回归应覆盖慢核验、期间文件变化、权限撤销、过期重放和两种时间范围。
2. **修复工具参数校验与恢复顺序。** 基线将 `actionId` 放进 `compute_evidence.args`，而协议要求顶层 `actionId`。当前实现先进入 `refreshStatus` 读取顶层标识、再做参数验证，因此缺失标识触发“该引用不在当前可读取范围”，流程无稿中止。应在查阅权限前检查参数形状，对形状错误提供可恢复纠正；若支持兼容归一化，只能接受无歧义位置，冲突或真实越权继续阻断。两版均存在这条实现路径，本轮只在基线触发。
3. **减少因限定语绑定遗漏引发的额外全量复核。** 候选将“现无材料决定取舍。”标成 unknown，但首次报告未显式绑定限定语，未通过本地标注规则，追加一次完整独立分类复核，花费 **18,750 tokens**。首次核验本身节省 950 tokens，无法抵消额外调用。应先促使首次报告准确绑定非事实结论的限定范围，验证常见未知表达；确需复核时再考虑只传待判结论和必要证据，同时保持证据作用域、原文锚点与完整语义检查，不能直接跳过复核。一次随机配对无法证明协议压缩导致了这次标注选择。

上述是后续建议，本轮未追加生产修复或真实模型调用。建议按此顺序做离线回归和独立代码审核，再提出新的小样本复测预算；在流程稳定、误拦消除且同完成程度总 token 有下降证据前，不启动正式主评测。
