# 推进用量和 100 美元等值上限

## 如何使用

- 委托详情和事项详情中的「推进用量与额度」显示全过程累计。委托的所有子事项、规划和检查共享一份额度；独立事项单独累计。
- 委托「运行记录」和事项「每次事项推进的模型与消耗」显示每轮输入、缓存输入、输出、合计 token 及已报告部分的折算费用。
- 「模型与设置 → 最近模型调用」可核对具体模型、重试次数、单价快照和 token。
- 默认上限 $100。追加时须先展开确认区，再确认追加 $100；若历史调用既缺失用量又没有预留，还须勾选知悉说明。取消不会改变额度。
- 恢复、重试、修改反馈和恢复备份保留累计值。增加模型调用次数不增加美元额度。暂停中的委托追加额度后仍保持暂停。

## 计量口径

输入总量包含缓存输入，合计 token = 输入 + 输出，缓存不能重复加到总量。费用分开计算普通输入、缓存输入和输出；接口报告缓存写入时按适用价格计入。每次调用保留当时的价格，不因后续修改模型配置重算。

内置参考表核对于 2026-10-12，来源为 [OpenAI API Standard 价格](https://developers.openai.com/api/docs/pricing)。例如 GPT-6.1 Sol 每百万 token 输入 $2、缓存输入 $0.10、输出 $10；超过 272K 输入时适用长上下文倍率，详见 [模型说明](https://developers.openai.com/api/docs/models/gpt-6.1-sol)。第三方接口可能有不同价格，必须配置自己的价格；内置表不按模型名称套用到任意代理服务。

订阅调用使用参考美元等值作为 App 内控制口径，不表示订阅余额、实际账单或已扣款。订阅额度和 credits 的实际规则由账号方案决定，见 [Codex 定价说明](https://learn.chatgpt.com/docs/pricing)。Ollama 默认计算费用 $0，不包含硬件和电费。自定义价格应包含所选速度档位、地区等加价；缓存价未填写时按普通输入价保守估算。

## 预留与结算

发送前检查剩余额度，按输入 UTF-8 字节数加协议余量、128K 输出预算预留；价格考虑缓存或写入的较高输入费率。预计无法容纳时提前停靠。返回后用报告值结算，并释放已确认的预留。失败或取消也记录已报告消耗；缺失用量时保留预留，若已知费用加全部预留仍能容纳下一次请求，则在原额度内继续。

这属于应用内预算控制，不是服务商账单硬上限。服务商通常在请求完成后报告用量；CLI 内部压缩和服务端行为也可能超出估计。一次在途请求可能越过 $100，结算后不再开始后续推进。确认继续不会抹去已有或未知消耗。

## 历史与恢复

费用账本 `spend-ledger.json` 独立保存于工作空间目录，发送前写入并 fsync。历史快照恢复不会覆盖此账本。记录损坏、缺失或无法保存时停止模型请求，不自动创建新额度。请连同工作空间保留账本，不要手动删除。

升级时根据保留的历史调用与能确认的价格回算委托；这是回算值，不能当作当时的实际账单。未报告、缺少原模型价格或已裁剪的调用明确显示为缺口，需要人工知悉后继续。升级前独立事项没有可靠调用归属，因此显示的新统计从升级后的调用开始。

外部搜索、办公服务、存储等单独收取的费用不包含在本次模型 token 预算中。

缺失用量但已有预留时，保留预留并在原额度内继续，不再要求逐笔知悉。只有旧记录既缺少用量又没有费用预留时，需要核对历史消耗；这不等于已经超出 $100。

## 每轮实际使用的模型

委托运行记录与事项推进记录显示本轮实际使用的全部模型、当时配置名称、推理强度、用途、调用次数、重试、备用调用及失败或中断次数。记录独立保存；更改模型配置或裁剪最近调用列表不会改写历史。执行中也会显示当前模型。

旧记录仅恢复能够按运行 ID 或唯一的委托及时间范围核对的调用，并标注历史可能缺失。尚未发出请求的推进显示“本轮尚未调用模型”。

长文修订采用唯一匹配的局部替换，未修改正文原样保留。片段不存在、重复、重叠或模型返回局部文稿时拒绝覆盖原文；修订仍计入同一推进额度，重新保存后接受独立检查。

## v0.33 推进恢复

已取消委托、规则和工作空间的模型调用次数上限，原调用记录及费用账本保留。人工点击继续前先检查费用和待补充问题；已有预留的未知用量不再阻止续跑，拒绝条件下不建立空运行记录。每批动作数用于自动接续与公平调度，不限制总任务长度。
