# R8 离线修复与下一轮预验收提案

2026-10-26。延续 [R7 根因审核](CONTEXT_ABCD_R7_LIVE.md)，本轮只修改源码、做离线回归和独立代码审查；没有调用真实模型，没有替换安装版。A–D 仍未通过真实模型验收。

## 修复范围

| R7 观察 | R8 实现 | 保留的限制 |
| --- | --- | --- |
| 生成请求在收到 `turn.started` 后触发两分钟本地空闲超时，未取得 usage | `processCall` 在成功、失败、取消、同步启动失败时记录本地退出信息；保留首次失败原因，记录单调时钟耗时、空闲时长、stdout/stderr 字节数、终止请求及协议事件时序；正确处理分块 UTF-8 和末行 | 本地停止不能证明远端未计费或正在推理。只有终端 usage 能结算；缺失、非法、冲突仍是未知，不替换为零或预留量。产品原有等待设置不变 |
| 外层 schema 只限制 `response_json` 是字符串，内部 JSON 出错；一次格式修复花费 19,832 tokens | 新增 `verification-output.cjs`，仅严格、非缓存的事项核验使用对象 schema；覆盖 compact-v5 报告、补读/求证、`retryFull`、缺新事实分支以及分类复核。可选 null 只按匹配的 schema 槽位归一化；必填 null、未知字段及字符串内嵌 JSON 拒绝 | 结构错误不会猜测性删改或自动退回字符串协议；普通生成、非严格核验、缓存确认和整体核验保留原协议。结构约束不证明业务结论正确 |
| 原文约束直接支持关系，却因正文缺少“推断”提示词而误拦 | 新增 `claim-semantics.cjs`：区分直接蕴含与引入额外假设的推理；直接蕴含须引用全部必要前提，反查主体、资源排他、范围和例外。同段明确前提、推理关系及适用边界可用现有 qualification 绑定 | 语义由独立 checker 判断；应用不凭关键词认定蕴含，不将原始 `passed:false` 转成通过，不扩大分类重核豁免。假设、因果、未知执行状态仍须支持与必要限定 |

协议升级为 `grounding v10 / compact-v5 / verify-input-v10`，旧通过记录不能沿用。结构 schema 的字节量和哈希进入调用归因、保守输入预算及费用预留；实际 input/output/cache tokens 仍来自供应商 usage，不能以“少一次修复”推断总成本一定下降。约 10 KB 的 schema 和新增可选字段可能增加每次核验成本，需要真实对照衡量。

Codex 的 `--output-schema` 用于约束最终结构，`--json` 是进程事件流；两者与业务证据验证分别负责不同边界。参见 [官方非交互执行说明](https://developers.openai.com/codex/noninteractive/)。实现使用现有订阅 CLI，不增加 API key 或新模型服务。

新增逻辑均位于现有 Windows/macOS 共用的 desktop JavaScript 层；本机验证环境是 Windows，未进行 macOS 应用运行或打包验证。本轮没有抽取新的跨平台包，也没有改变安装位置。

## 离线证据与审查

回归覆盖真实应用调用链的受控模型/CLI 替身、严格核验、原文位置绑定、分类重核、输入预算、费用预留、回执与持久化、读取/计算/补证/修订及旧协议兼容。替身测试验证代码与边界，不是模型准确率测试。

独立审查发现 schema 遗漏 `list_sources` 的 `ref/type/taskId`，会阻断已有章节目录与任务目录导航。已补齐并加入回归；同时完整保留修订 `gapDetails` 的 `artifactId/stepId/kind`。

扩大回归还定位到既有飞书缺陷：`lark_update` 仅覆盖正文，并不发送标题；此前把内部 `record.title` 纳入发送标题，导致准备覆盖动作就使刚通过的内容检查失效。修改前的独立基线中，两项旧状态恢复测试同样失败。现仅排除该内部标签，正文精确匹配、事项/稿件标题以及真正发送的创建、GitHub、邮件标题继续核验；原恢复测试断言未弱化。两项真实子进程测试增加冷启动余量，但仍证明持续输出超过空闲窗口及总截止有效；一项旧上下文测试改查已有 `userDirectives` 投影中的相同反馈。

独立审核初轮相关回归 118/118、导航修复后重复检查 12/12、最终标题/写入竞态/超时补充回归 55/55 通过，各轮有重叠，不相加宣称唯一测试数。最终无剩余可复现阻断，见[独立审查记录](evaluations/abcd-readiness-r8-offline/code-review.json)。Windows 原生辅助构建及 Vite 生产构建通过，保留原有大 bundle 提醒；未构建或安装发布包。最终扩大回归覆盖 56 个测试文件、1,037 项：首次 1,032 通过、2 失败、3 跳过；两项失败为旧飞书测试将 Windows 8.3 短路径与长路径直接比较，修改前基线也同样失败。仅将测试改为子进程内 native realpath 后相对目录严格等于 scratch，保留 HOME、账号、来源及清理断言，两项复测 2/2 通过并经独立复审。按唯一用例计，最终 1,034 项通过、0 项未解决失败、3 项跳过；不是一次全绿运行，也不重复累计前轮检查。跳过项为两项需要 Windows 文件符号链接权限的场景，以及未设置专用 v3 冻结基线环境变量的一项兼容探针。详见[回归摘要](evaluations/abcd-readiness-r8-offline/regression.json)。

R7/R6 冻结实现、题目、执行器、账本及结果不修改，不用旧样本宣称新模型质量提升。R7 的用量未知仍未知；旧误拦记录仍保留。

## 待批准的真实模型复测

建议仍为 **6 组全新配对、最多 96 次真实调用、200 万 input＋output tokens**，任一上限先到即停。范围是 R8 预验收，不启动正式主评测。R6 曾在 59 次调用、1,172,572 tokens 内跑完六组尝试；该历史数据仅用于预算参考，不能保证本轮所有分支完成。旧轮剩余额度不结转。

1. 代码与执行器冻结后，由独立作者新编样本并封存 gold；执行器不读取 gold。R7 基线固定为 `2a76025a278d1f8bbe70f48afe7601189fd9ac6e`，R8 固定为本轮最终审查通过的提交。
2. 两组固定稿分别测试“全部前提明确的直接蕴含”与“缺必要前提/伪称执行完成”的判定。其后四组动态任务覆盖长文例外与确定性计算、90 秒历史观察和当前回读、元数据标题与正文标题分别修订、最新要求替代与整体独立检查。题目、数值、名称和材料不得复用本轮开发样本。
3. 两版使用同一 `gpt-6.1-sol / medium` 订阅配置，串行、交替先后顺序。先完成固定稿配对，确认真实 CLI 结构协议能形成有效结果，再进入动态组；这属于同一六组预算，不另加探针。
4. 在新的外层执行协议中，对双方统一预注册 **15 分钟空闲、20 分钟总时限、transport retries=0**。15 分钟与产品默认空闲设置一致；这是避免重复两分钟截断的新测试上限，尚非经实测证明的最优值。计时与用量事件单独记录，不因 stderr 活动声称业务进展，不修改旧封存协议或用户当前设置。
5. 每分支每阶段最多 12 次；生成、规划、补证、事项/整体核验、修订和任何格式恢复全部进入同一总账。未知/非法/冲突用量、结构协议不兼容、代码或题目哈希变化立即停全局，不自动重试、加额、复跑或增加第四轮。
6. 独立审核先隐藏版本与成本裁决内容，再核对流程、分母、账本和哈希。报告流程完成率、已验收稿幻觉率、合格稿误拦率、不合格稿错误放行率及各阶段 tokens；固定稿与动态稿分开。零分母写不可估计，不写零风险。

预验收关注候选是否能走完四组动态任务的完整生命周期、两份固定稿判定正确，以及已观察到的错误放行或已验收幻觉是否为零。所有质量率报告分子/分母和区间；六组不足以证明总体不劣。成本同时报告全部尝试，以及双方都完整且业务正确的配对；后一集合为空则同等质量成本改善不可估计。无论结果如何，本轮不自动启动正式主评测或安装替换，先独立审核并上传结果，再确定下一步。
