## 已落实的控制

- 预算在实际 CLI 转发前持久预留，应用调用、CLI 请求和账本对账。未知用量以 null 表示，已知部分另列，失败不能抹去已知消耗。
- 同一批准绑定唯一 runId、固定输出目录和执行器身份，一次消费；换目录或重用均拒绝。
- 每次准入/重启检查冻结 EXE、ASAR、执行器、调用/取消依赖及 unpacked Windows helper；真实 CLI 另绑定批准时的哈希。
- 禁止隐式 JSON 修复和局部修订失败后的自动重写；允许原产品的合法读取、增量检查请求全文、核验缓存协议及预定精确修改。
- 取消、超时、协议拒绝和未知用量结束整轮；等待进程树退出，成功与失败均保留原始响应及 usage 事件。
- 门检和 F03 初稿有独立内容检查点，审查者先看原文、要求、当前稿，再提交绑定回执。回执不进入业务状态或模型上下文。没有回执不默认通过，不重置45分钟发起窗口。
- 正例最后保持 review，两个固定错误稿不可接受且字节不变；执行器没有真人接受的操作权限。

## 离线验证口径

单元测试114/114通过，独立审核者另行复跑同样114/114通过。覆盖账本、转发与进程树、协议、独立审查检查点、一次性授权。真实安装包集成预演5项均达到预期：

| 场景 | 预期 |
|---|---|
| 门检 + 六例完整预演 | 7个技术流程通过；22次合成调用；两次重启无新增调用 |
| 错误外层 JSON | 门检1次后停止，不追加格式修复，不进入业务样本 |
| 错误内层 JSON | 门检1次后停止，保留原响应及已知用量 |
| 缺少权威 usage | 门检1次后停止，总量未知，保留错误回执 |
| 案例预算准入拒绝 | F01降低的离线预算拒绝核验；保留该例失败，后续五例继续执行 |

采用差分验证：完整流程及三项协议故障在执行器v1（`1bbb1c57…`）下完成；最终v2（`9eaa05b4…`）仅修改案例预算拒绝的整轮停止判定，以及对应离线注入、断言与说明，再单独补测该分支。没有把前四项冒称为在v2上重新执行。

最终实际结果见 [验证记录](evidence/foundation-runner-verification.json) 和 [独立审核](evidence/foundation-runner-review.json)。合成调用及合成 tokens 只检验流程和账本，**不构成模型幻觉率、误拦率、错误放行率或真实成本证据**；这些指标目前均为待真实验收。
