## 下一轮全新样本方案（待批准）

仍先做 **6 组配对预验收，共 12 个分支**，不启动正式主评测。代码审核和冻结后新编六题，题目、gold、实现、驱动和计量协议一起封存。评测执行器不读取 gold；发生实质代码修订后本组只能用于诊断，不能再冒充独立新样本。

| 组别 | 数量 | 必须实际覆盖 |
| --- | ---: | --- |
| 固定稿 | 2 | 一份合格的来源冲突/未知说明；一份含错误完成或回执断言的稿件。只核验，不自动修稿 |
| 端到端 | 2 | 多证据组、末尾例外和两次显式计算；历史文件观察、新材料读取、原事项补证恢复。只读任务没有新增文件交付义务 |
| 验收后修订 | 2 | 初稿整体检查和真实验收后，改变范围/数值/标题或例外，再重开、修订、完整核验、再次验收 |

沿用此前封存的稳定基线，两版都开启严格核验；候选为本次审核后冻结实现。两版使用相同模型及推理配置、同样权限和业务输入，交替先后顺序、串行执行。能力差异和技术失败单列；不能把旧版缺少新工具直接计为幻觉或误拦。

建议新额度：**最多 96 次真实模型调用、2,000,000 个输入＋输出 tokens**；每个分支每个阶段最多 12 次、并发 1。生成、规划、补证、事项核验、整体核验、格式/分类恢复、失败请求及两个修订阶段全部共用额度，不另开诊断或自动复跑预算。缓存输入属于输入，不重复相加。

预算依据：R5b 实际 50 次用了 955,117 tokens，约 19,102 tokens/次；按 96 次外推约 183 万，加上保守单次输出预留所需尾部空间，建议上限 200 万。预计 60–80 次、约 115–153 万只是容量估算，流程修复后实际输入分布会变化。每次发送前仍按输入字节、输出与包装预留做保守总账准入；剩余额度不足、用量未知或封存不符即停止，不通过缩小真实预留凑满题数。没有本轮新批准则不发起调用。

报告同时提供：

- 流程完成率：固定稿完成有效检查，端到端和修订完成规定的验收链；分别给出分子、分母与技术未完成数。
- 最终模型生成交付的幻觉率，另列所有已通过阶段；固定注入错误稿不混入模型生成幻觉。
- 合格固定稿误拦、错误固定稿放行；动态稿由独立内容审查判定合格性后另报误拦/错误放行。整体检查未运行或 usage 未知不当作模型误拦。
- 两版实际输入、输出、缓存输入、总 tokens，以及生成/规划/补证/事项核验/整体核验的分项。全体尝试成本与“配对两版都完成”的任务成本分别报告，避免用提前停止造成的低消耗冒充节省。
- 所有零分母标为不可估计；比例附样本数和区间。六题只能判断流程是否值得进入正式验收，不能证明幻觉率统计不劣。

进入正式评测的前提是候选四条动态链全部闭环、两份固定稿正确判定、没有观察到错误交付，并且逐调用账本完整。若基线或候选未完成足够配对任务，则明确无法判断同等成功任务的 token 改善。完成后再据实际失败类型和成本确定正式评测设计、预算及是否部署，不自动追加一轮。
