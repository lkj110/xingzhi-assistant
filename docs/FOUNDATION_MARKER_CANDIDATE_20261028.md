## 实际包离线结果

新增 `scripts/marker-candidate-lifecycle.cjs`，只运行独立候选、全新 profile 和随机路径保护的 loopback HTTP 模型替身。链路为实际 renderer → IPC → Worker → HTTP 适配器，未导入源码 Assistant 替代实际包。每次启动都核对 EXE 包清单、ASAR、应用版本及 Worker 实际加载的核验模块。

成功场次完成 5 次启动、18 次替身请求（4 次生成、14 次核验/读取交互）。文稿使用上一轮已独立审查的 P01 修订参考稿原字节，proposal 类别、条件与引用没有为取得通过而改写。这是已暴露回归材料，不是全新模型样本。

| 场景 | 结果 |
| --- | --- |
| M01：完整人工确认通路 | 初检进入 waiting，核验仍为 false；等待重启不调用模型；实际界面确认零调用；确认后重启保留身份；普通推进和提前验收被拒绝 |
| M01：显式重检与验收 | 另点“重新核验”仅核验/读取，不生成新稿；即使 autoComplete=true 仍停在 review；自动化点击“验收完成”后才 completed，重启保留结果 |
| M02：确认后独立拒绝 | 注入不支持/未解决冲突，结果 blocked，不能以表达确认或普通验收放行 |
| M03：错误引用 | 原文不匹配时直接 blocked，不进入表达待确认，确认和验收均被拒绝 |
| M04：要求变化 | 旧表达确认不能用于新依据；重新核验后再次 waiting，保留原稿，等待新的人工处理 |

M02/M03 是合成核验响应的故障注入，不用于估计幻觉率、误拦率或错误放行率。自动化点击只证明人工命令通路可运行，**不等于真人阅读、确认或验收**。18 次替身用量固定为测试数值，不能作为真实 token 成本。此次也没有测试官方 Codex CLI 的在线协议或计费对账，下一轮仍需真实协议门检。

首次生命周期场次在导入资料时因现有接口每次仅接受一段文字而停止，替身请求为 0。仅修正测试脚本为逐段导入两份原文，保留独立来源身份后，在新输出目录完整重跑通过。原失败结果、退出码、截图和隔离工作空间保留；未修改产品代码或旧样本。

运行结果、冻结记录及独立审核分别见[验证汇总](evidence/foundation-marker-package-verification.json)和[独立审核](evidence/foundation-marker-package-review.json)。当前安装 86 文件、旧候选 86 文件及四套历史包 47 文件保持原字节。此补丁已在独立候选包加载，**尚未部署到当前安装版**。
