## 两项修复的边界

通知语气：已有来源支持、符合当前用户通知要求的祈使句，不应仅因没有“建议”等字样被否决。候选修复只调整该局部标记检查，仍检查当前稿件原文、授权且已读来源、逐字引文、结论支持、要求满足与冲突。它不把任意带“请”的句子视为可信事实，也不能代替独立模型对对象、动作、日期和条件的语义判断。

格式错误停止：在评测器返回响应成功之前，检查核验报告嵌套字段的结构、既有上限和编号格式。`unsupportedClaims` 和 `conflicts` 接受字符串数组，冲突对象不能被当作普通业务缺口。格式错误沿用整轮停止链，保留原始响应、错误位置和已知用量；结构合法的 `supported:false`、要求缺口和冲突仍属于业务不通过。候选提示词明确 `conflicts` 的已有字符串数组类型；这不保证模型以后不会再犯格式错误，发生时必须停轮。

通知的局部豁免要求当前可信用户输入包含通知任务、已满足的要求关联该结论、独立核验给出 `supported:true`、至少一条有效已读原文引用，且结论是单句 `proposal` 祈使语气。未知和推断不获此豁免，逗号、句号、冒号或分号拼接的混合断言也不获此豁免；复杂多分句通知可能继续保守阻断。

输出 schema 未增字段，生成提示词维持 472 UTF-8 字节；核验提示词 2,157→2,341，增加 184 字节（通知语义说明 163、冲突类型澄清 21）。这只是字符串字节测量，不是实测 token，不能据此声称本轮降本。

协议/格式拒绝、未知或冲突用量、冻结身份变化、全局额度异常立即停止整轮；不自动续跑、不使用历史剩余额度。700,000 是准入与停止阈值，当前接口不能强制在途请求绝不超额；新预算须单独明确批准并接受此限制。
