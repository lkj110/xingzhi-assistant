2026-10-27。修复基于 R9 实现 `38ff396103692f6f51013fe524a279f85e431ed9`；本轮起点为其结果报告提交 `bacf826b21dbab940c00bd6e1133b5250fbcdd23`。本报告所属提交包含 R10 实现。本轮仅离线测试和独立审核，没有真实模型调用、正式主评测或已安装应用替换。

## 修复及边界

### 1. 回执的时间语义

R9 中 `action_status` 的文件比较在核验开始时新鲜，模型返回时越过 60 秒期限，整个回执被排除。新版在实际文件比较时记录观察身份、原文、哈希、时点和显式求值事件。复用 `file-observation` 的身份与权限检查，区分两种用途：

- 当前状态仍使用 `valid()`，保留 60 秒时效和实际状态校验；外部交付规则保持原样。
- 明确观察时点的事实通过 `readable()` 取得历史证据。仅支持由应用实际捕获且观察身份仍有效的本地文件比较，权限、记录身份、内容完整性、执行事件必须仍有效；后来文件改变/删除不改写已发生的观察。旧回执没有捕获身份时，不能通过内部复算升级为历史证明，必须显式重新读取。

`claim-observation.cjs` 复用既有 `qualification` 的字段、位置、可见性及完整结论绑定，不增加输出 schema 字段。历史用途须绑定同句观察时点，例如“本轮只读核验时，…”或准确的 `observedAt`。原文引用、内容语义、对象与适用范围仍由独立核验判断；本地时点锚点不证明语义为真。无时点、跨字段/段落借用时点、过期证明“现在仍一致”或肯定交付仍被拦截。

独立审核指出全句关键词检查会误拦“文件正文为‘当前计划’”以及“不证明文件现在仍一致”等合法文字。已改为只遮罩明确归属的文件原文引述，以及完整匹配的否定分句；始终用原始文字进行精确绑定。引号外或否定后新增的肯定断言保留检查，任意引号不能隐藏断言。该规则支持有限的明确时点结构，不宣称能靠正则穷尽自然语言语义。

审核还发现“任务核验很快通过，委托目标核验（`goal_verify`）很慢跨过 TTL”的缓存问题。已改为稳定观察身份进入基础缓存键，再逐条检查已核验引用的用途：新鲜时成功绑定时点的引用也立刻标记历史用途，跨 TTL 后仍可复用；当前用途仍须新鲜。同一回执被历史和当前结论共享时，各自保存引用副本，互不污染。仅历史用途不触发额外当前文件回读；真实撤权或记录变化仍使缓存失效。

### 2. 工具参数校验与恢复

`compute_evidence` 在查找动作、刷新或读取文件前先验证请求形状。`action_status` / `file_observation` 要求顶层非空 `actionId`；嵌套、歧义、空值、非法 `inputs` 或自报结果返回可纠正参数错误。不会自动猜 ID 或把两个冲突位置合并。

参数错误沿用现有有界纠正额度，不新增循环。只有本模块标记的参数错误可以恢复；真实越权、资料版本变化、读取器错误、暂停和取消继续停止。错误请求不产生工具证据或求值事件，纠正后的真实执行才记录回执。

### 3. 首次报告限定语绑定

首次核验明确要求每条非 fact 结论提供 `qualification`。如果结论本身已经完整表达限定，就精确绑定自身；相邻限定语及不常见表达同样绑定，不能只写在 reason 中。schema、字段类型和原来的有界独立分类复核均保留。

补充了有限的完整缺证句识别，包括 R9 的“现无材料决定取舍。”。它只能在同一实际可见字段内自绑定，不能包含后续肯定分句，也不能改写模型的 `supported:false`、冲突、要求缺口或最终拒绝。离线生产路径证明：已读来源后的首次报告可以通过，无需追加分类调用；不能据此推断真实模型总 token 已下降。

Grounding 升至 12，输入协议为 `verify-input-v12`，新模块纳入实现身份，旧通过结果不会静默沿用。新增纯逻辑模块与已有回执身份模块分工明确，Windows/macOS 的同一 JavaScript 核心可以复用；本轮实际验证环境为 Windows，未声称完成 macOS 原生运行测试。

## 输入开销

同一离线样本对比 R9，所有阶段的输出 schema 字节数不变：普通读取 8,461、合成增量分支 8,593、基础读取 6,785、结论/分类 4,641。新增时间语义说明后，默认启用 B/C 的各阶段完整可见输入约增加 **318–319 字节（1.04%–1.31%）**；关闭 B/C 的基础分支减少 31 字节。正文/引文唯一内容集合 hash 配对一致；合成增量输入含运行时元数据，可有约 1 字节波动。

这是序列化输入加 schema 的 UTF-8 字节，不是 tokenizer 或供应方 usage，不含隐藏包装与模型输出。该普通样本没有代表所有文件回执长度，不能外推为业务总 token。增加明确的必要语义，用减少误拦与额外全量复核争取总成本收益，仍须真实模型复测。完整数据见 [R10 输入测量](CONTEXT_ABCD_R10_INPUT.json)。

测量脚本原先把基线版本固定标成 R8，本轮发现并修正：第四参数可显式记录完整提交 SHA，省略时为 null；本次基线确为冻结的 R9 目录。复现形式：

```text
node scripts/verification-protocol-measure.cjs <R9目录> <输出JSON> 38ff396103692f6f51013fe524a279f85e431ed9
```

合成增量行仍只用于通用接口覆盖；实际缓存复用常沿用旧包装，不能把合成行当作所有增量业务的普遍开销。
