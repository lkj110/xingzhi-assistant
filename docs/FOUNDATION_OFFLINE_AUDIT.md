# 基础版四项残留测试的有界离线排查

日期：2026-10-28。基线为 `cba955e4b5826ae72ad8f3d414214b5a548fdb6e`，工作分支为 `codex/foundation-offline-audit`。当前安装的 Windows Foundation 2026-10-27、稳定分支和发布标签保持冻结。本轮无真实模型调用、外部文档读写或安装操作。

## 结束条件

按子进程活动、连接器就绪/清理、完整 Worker 交付、授权恢复顺序排查。每项最多两次诊断修订，然后做受影响范围复测。不能复现的旧失败保留“原因未确定”，不通过循环重跑把它改记为已解决。独立审核发现的问题允许一次有针对性的修正和核验。全量 Windows 回归不在本轮重跑范围。

## 四项结论

| 项目 | 本轮证据 | 原因与处理 |
|---|---|---|
| 1. 子进程活动延长等待 | 实际 processCall、实际受管 Windows 子进程及原过滤环境下，200 ms 窗口三次失败；相同输出程序仅改为 1000 ms 后成功。初始活动到首次输出分别约 529 / 290 / 282 ms，对照约 271 ms | 确认测试的首次输出预算过短。修正测试为 1000 ms idle、16 次每 100 ms 输出，流总时长仍超过 idle；保留至少七次活动断言，增加完整输出检查。生产默认 15 分钟策略不变。 |
| 2. 飞书 abort-transient-probe | 原 5 秒准备等待、原清理断言下，单项通过；随后 I13 四个案例也通过。三个进程就绪耗时 3.58 / 4.26 / 4.04 秒 | **历史失败未复现，根因未确定。** 准备阶段包含身份校验和多次 Windows 权限检查，时间接近 5 秒只构成线索。新增阶段诊断、准备失败时取消并等待同步退出；不扩大等待窗口，不宣布产品问题已修复。 |
| 3. full-delivery check-revise | 修改共享夹具前，以原断言、原 60 秒限制通过，耗时 19.73 秒；修改后目标复测通过，耗时 21.24 秒 | **历史超时未复现，根因未确定。** 增加 Worker 阶段和末尾审计摘要。不能把本次通过解释为已证明旧失败由机器负载导致，也不代表真实外部交付已认证。 |
| 4. 授权修复跨重启 | 修改前两次观察超时；第二次定位为恢复后的第七次观察，15 秒没有回复，但审计已推进到 17 次合成输入和更新/回读。修改后目标复测通过，耗时 29.77 秒；63 次观察均返回，最长约 3.35 秒 | 确认立即完成的合成 transport Promise 连续推进，导致测试 Worker 的消息端口得不到事件循环轮次。夹具增加 setImmediate 模拟 I/O 异步边界。单次观察仍限 15 秒；完整恢复等待由 15 调为 45 秒，外层仍限 60 秒，并增加执行中必须能观察到 busy 的断言。**属于修改条件后的通过，不是原条件通过。** |

第 4 项结论仅覆盖该合成夹具。没有证明生产 Worker 在所有本地连续计算、缓存调用或取消场景下都能及时响应。保留这一边界，不据此改动产品调度。
