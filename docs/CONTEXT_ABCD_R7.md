# R7：历史观察、标题修订、要求投影与整体核验证据

2026-10-26。本轮按 [R6 真实模型结果](CONTEXT_ABCD_R6_LIVE.md) 的四项优先级修改，实现和验证限于离线环境。真实模型调用 **0**，实际模型 tokens **0**；没有新的幻觉率、误拦率或错误放行率结论。A–D 仍须新样本验收，当前安装版没有替换，正式主评测没有启动。

## 四项修改

1. **历史观察与当前状态分开。** 新增 `file_observation`，记录 `observedAt` 时点的完整文件比较、正文哈希、原动作身份和明确的历史边界。引用时重查当前任务、动作、原稿及文件目录的可读授权，检查回执完整性与显式执行事件；不重新读取文件来冒充过去的观察。`read_local_result` 对历史 `write_file` 使用该操作。`action_status` 继续要求新鲜状态、保留 60 秒有效期；历史观察不能授权当前文件交付、发送或其他外部动作。
2. **元数据标题与正文标题分别修改。** 新的标题约定提供正文 H1 的原始位置，明确 `title` 只修改元数据；需要改变文档标题、版本或对象时，正文标题必须显式进入 `edits` 或完整 `content`。保留只改元数据的能力、精确片段匹配、失败时保留原稿和独立全文核验；不会机械替换历史引用或同名章节。
3. **当前要求与历史记录分开。** 可信用户编辑在首次变更时保存旧字段。单事项原委托中与被替代旧字段完全相同的行可退出当前要求清单，其历史与哈希仍可追溯；共享、复合或无法明确判断的义务不自动删除。用户补充按事项范围投影，原文与旧显示前缀副本合并，重复重申保留最新顺序。更新单个事项不会覆盖整个委托或其他事项。
4. **整体核验预先取得有界原文。** 独立整体检查之前通过现有权限与版本校验读取最多 8 个输入来源、48,000 字符；已经完整读取且仍有效的同版本来源不再读取。保留原文及例外、分页 `coverage/next`，实际模型输入仍经过预算和裁剪。准备记录不宣称模型已完整看见；超限部分须继续读取。旧检查结论不能替代原文或本次独立判断。

新增模块分别为 `file-observation.cjs`、`revision-title-contract.cjs`、`requirement-projection.cjs`、`goal-evidence.cjs`。它们位于共用桌面业务代码中，不依赖 Windows UI；尚未执行 macOS 原生打包或平台集成认证。严格核验协议更新为 `grounding v9 / compact-v5 / verify-input-v9`，旧缓存不能直接授权新协议的交付。

## 离线验证与审核

初轮扩展回归：33 个测试文件，**528/528 通过，0 失败、0 跳过**，包含旧冻结基线的严格核验生命周期兼容性。新增覆盖慢调用后补证—生成—事项核验—整体核验—验收，文件变化/删除、权限撤回、伪造回执、重启、正文旧标题、重复标题、共享要求、用户补充去重及长文末尾例外。

独立 subagent 发现四项 P2 并在修复后批准：旧要求在其他生产入口重新出现、同时间戳补充丢失、多行重申丢失最新顺序、要求版本与缺口生命周期未同步。第四项首次修复导致旧有效缺口失效，兼容回归发现后已补齐一次性迁移：保留未改变意图的旧有效缺口，真实退役目标仍使旧缺口失效。

最终扩展回归 **42 个测试文件、687/687 通过，0 失败、0 跳过**；独立审核复跑 **19 个文件、339/339 通过，0 失败、0 跳过**，无未解决 P0–P2。两轮范围重叠，不相加为独立样本数。审核前后 16 个生产模块和 19 个测试文件哈希一致；另记录 LF 归一化哈希供上传核对。Windows 生产构建成功，保留已有的大于 500 kB chunk 提示；未生成新安装包。

模型 transport 使用离线替身；生产状态转换、读取、权限、版本绑定和验收门槛照常执行。合成 usage 只用于验证记账，不当作实际模型成本。详见[离线验证记录](evaluations/abcd-readiness-r7/offline-review.json)及[独立审核原始记录](evaluations/abcd-readiness-r7/independent-code-review.json)。

历史文件题计划在观察完成后的预定阶段加入至少 90 秒评测等待，两版一致，不改系统时钟；等待计入流程时间，不占模型调用。这一条件须写进封存协议，检验真实慢调用间隔下的观察证据接续。状态变化、撤权和伪造等破坏性边界继续用隔离离线回归覆盖。

建议额度：**最多 96 次真实模型调用、2,000,000 个输入＋输出 tokens**；并发 1，每个分支每阶段最多 12 次。生成、规划、补证、事项和整体核验、格式恢复、失败请求及修订阶段共用总账；缓存输入已包含于输入，不能重复相加。每次发送前按输入、输出与包装预留准入；用量未知、封存不符或剩余额度不足即停止。剩余额度不授权额外探针、复跑、第二模型或正式主评测。

预算依据：R6 实际 59 次调用消耗 1,172,572 tokens，约 19,874 tokens/次。按 96 次外推约 191 万；预留 200 万上限，仍以实际准入为准。60–80 次、约 120–160 万只是容量估算，修复后的流程深度及输入分布可能改变，不承诺节省。
