## 实现

- schema 使用 `$defs` 复用字符串数组、可空类型合并重复分支；报告的字段、类型和绑定信息不删减。发送 schema 与本地 decoder 由同一组类型节点生成；本地只移除显式可选字段的 null，不猜语法、不修复语义。
- 普通补证允许完整报告、资料请求和真正需要用户决策的出口；B/C 工具随本地功能开关选择；只有增量输入允许 retryFull。
- 有界结论、独立分类复核使用完整报告专用 schema，移除读资料、搜索、计算、need_input 和 retryFull 输出分支。保留资料/回执的解释规则和完整证据标准。
- schema 已定义的结构示例、枚举从订阅模型提示词中移除。模型路由和已授权 fallback 之后再按实际 provider 选择提示词；HTTP 模型保留文字结构说明，JSON 修复消息不会被普通提示词覆盖。
- 输入协议提升至 `verify-input-v11`、grounding 版本 11，缓存身份纳入协议和提示词组件；旧通过结果不会因仅改传输方式而被静默复用。

复现：先将基线提交用 `git archive` 导出到独立目录，再运行：


脚本执行真实的上下文准备、预算、路由和可见性逻辑，最终 transport 是离线替身。测量中的模拟 usage 仅服务测试结算，不作为 token 结果输出。对应结构化记录见 `docs/CONTEXT_ABCD_R9_INPUT.json`。

## 证据与语义保护

未改变本地证据可见性/作用域校验、逐字引文与稿件锚点绑定、要求覆盖、来源冲突放行条件、资格限定、全文一致性和交付回执判断函数。新版提示词仍要求：

1. 每条要求恰好一次，完整扫描当前稿件与标题，覆盖关键结论；旧稿或生成者自评不作独立证据。
2. 引文来自实际提供的原文；限定语必须约束同一条完整结论，不能把肯定断言藏进 unknown/inference；锚点只证明位置，不证明语义。
3. 披露冲突只有在要求允许未知、双方引文均绑定所列结论且满足范围条件时才可接受；要求确定、选边或隐瞒仍阻断。
4. 全文一致性保留两处逐字锚点；证据不足不能以局部核验替代整稿通过。
5. 计算必须有来源绑定和明确口径；历史文件观察不能证明当前交付，action_status 仍受新鲜度约束，计算回执不证明原始业务数据真实。

离线结果支持“协议和本地守卫未削弱”；真实模型是否更易漏报或误拦，必须由新样本对照检验。

## 原真实模型复测提案（已获批并完成）

以下保留实施前提案；实际结果见 [R9 真实模型复测](CONTEXT_ABCD_R9_LIVE.md)。没有自动启动正式主评测。

建议采用一个总预算、两个连续门槛，最多 **80 次应用 transport 调用、1,600,000 输入＋输出 tokens**；两项任一先触顶即停，不追加预算，不自动启动正式主评测。

1. 协议门检：最多 8 次、160,000 tokens。基线/候选各 4 次，用全新资料覆盖普通读取、计算请求、有界结论、分类复核；核对输出 schema 接受、完整生命周期、实际 usage 和持久账本。任意未知用量、协议拒绝或无法结算立即停止，不进入业务复测。
2. 小样本业务复测：门检通过才执行 6 组全新配对（12 分支），最多 72 次、1,440,000 tokens，每分支最多 6 次。2 组固定稿（正确/含错各一），4 组完整流程含补证、来源分歧、数字/条件、标题限定和当前交付证据等情形；任务须按调用上限设计，不能删减核验标准来凑预算。
