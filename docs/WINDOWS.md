# 行知助手 Windows 版

基于上游 `lkj110/xingzhi-assistant` 的 0.42.4 源码，Windows 适配修订 4。保留原有业务功能，并实现截图、划词、OCR、通知、飞书固定账号会话等 Windows 平台能力。构建由源码独立打包，未使用发布者的代码签名；修订 4 的验收进度见 [状态记录](WINDOWS_R4_STATUS.md)。

面向 Windows 10/11 x64；本次实际测试环境为 Windows 11 x64。Windows 10 和多显示器混合缩放尚未实机验收。

## 启动与更新

解压整个文件夹，双击 `XingzhiAssistant.exe`。保留旁边的 `resources`、DLL 和其他运行文件，不要只复制 EXE。基础运行无需另装 Node.js、Python 或 Swift。

首次启动可跳过模型配置，直接保存材料。AI 整理和推进需要在「模型与设置」配置自己的模型服务或已运行的本地模型。应用不附带账号、密钥或额度。

工作空间默认位于 `%APPDATA%\行知助手\workspace`，与程序文件分开，以应用设置中的实际路径为准。更新前暂停自动托管、退出程序并备份工作空间，然后将新版本解压到新的文件夹。关闭窗口后应用留在系统托盘；右键托盘图标可退出。正常启动会创建或更新当前用户的开始菜单入口，用于通知身份和快捷启动。

## 桌面功能

- `Ctrl + Shift + Space` 打开快速收集，`Ctrl + Shift + 2` 框选截图。截图时拖动选择范围，Esc 或右键取消。
- 选中文字后出现收集工具栏。支持系统选区接口的控件直接读取；未提供选区接口的普通文本控件可在点击工具栏后尝试复制读取，并恢复原剪贴板。不持续读取剪贴板，不读取密码控件。
- 其他应用的权限或控件实现可能阻止划词读取；可复制后在收集小窗粘贴。管理员权限窗口仍受 Windows 权限边界限制。
- 图片、旋转照片和扫描 PDF 使用本机 Windows OCR。中文、英文识别依赖系统已安装的 OCR 语言组件；缺少组件时按应用提示安装对应 Windows 语言功能。OCR 不调用模型。
- 支持系统托盘、任务栏待处理角标、通知、工作时段、后台托管、暂停及恢复。系统通知显示还取决于 Windows 通知开关和勿扰设置。

## 模型、连接器与能力中心

全部入口沿用原应用，完整用法见随包内置的《使用说明》。

| 功能 | Windows 配置 |
| --- | --- |
| DeepSeek、Kimi、OpenAI、Claude、Gemini、Azure 及兼容服务 | 在模型设置填写自己的地址、模型和密钥。支持原有模型路由、故障接续、预算、用量和上下文控制 |
| Ollama、LM Studio 等本地模型 | 先在本机启动对应服务，再填写其接口地址与模型 ID |
| ChatGPT / Codex 订阅 | 安装原生 Windows Codex CLI 并自行登录；自动检查 PATH 和 npm 标准安装目录 |
| 飞书 / Lark | 安装 Windows `lark-cli` **1.0.65** 并完成对应账号和应用授权；此版本与上游固定账号协议一致。原生 EXE 放入 PATH，或使用标准 npm 安装目录 |
| 飞书消息、文档、日历、交付 | 使用上述 CLI；读取时固定账号，写入仍遵守原应用中的授权与确认规则 |
| 企业数据平台 | 安装并登录组织提供的 Windows `bytedcli`；支持原生 EXE 和标准 npm JavaScript 入口 |
| 本地与远程能力仓库 | 远程仓库操作需要 Git for Windows；DW Python 脚本需要 Python 3 并加入 PATH，中文按 UTF-8 处理 |
| MCP | 安装对应 MCP 服务的运行环境；保留原有 stdio 工具接入。建议 Node 服务填写 `node.exe` 的绝对路径并提供脚本参数，也支持 SDK 识别的标准 npm 命令 |
| GitHub、办公 API、网页、RSS、本地目录 | 按原界面配置地址、目录和相应账号凭据 |

这些外部服务仍需用户自己的账号、权限、网络和服务端能力。外部办公服务使用模拟接口测试；本机现有 ChatGPT 订阅的三种模型和图像生成另有真实调用记录。没有办公服务真实账号验收时，不应将连接器模拟测试描述为账号已接通。

## 修订 3 的本机工具

能力中心增加本机工具：检测独立 Git/Node/Python/飞书 CLI，配置专用资料和交付目录，挂载本机只读资料 MCP。运行环境位于 `%LOCALAPPDATA%\Programs\XingzhiAssistantTools`，作为 PATH 的补充，不覆盖显式 PATH 中的有效工具。

- Python / JavaScript 可手动执行，当前用户权限，独立运行目录，60 秒及 500 KB 输出上限，全局停止会结束进程树。
- 邮件可保存 `.eml` 草稿；已授予 Mail.Send 的 Outlook 连接可逐封预览、确认发送。请求被服务受理不等于收件人收到。
- GitHub Actions 可预览并触发指定仓库中已有的 `workflow_dispatch` 工作流，需要 Actions 写权限。受理请求不等于部署成功。
- 图片使用当前 ChatGPT/Codex 订阅调用图像工具，消耗订阅额度，限新图片生成。此入口依赖当前 CLI 的 code mode；不改变原文本推理通道的工具限制。
- 语音使用 Windows 离线语音包，输出 WAV；中文需系统中文语音。此功能不提供音乐合成、语音克隆或视频生成。
- 手动入口继续可用；修订 4 也将这些工具接入 Agent 自动规划、执行与核验。记录中断或提交结果未知时不会自动重试。

## 修订 4 的 Agent 工具

创建委托时展开「新增工具权限」，分别设置代码、邮件草稿、图片与语音、Outlook 发信及 GitHub 部署权限。已有委托可在空闲时调整权限；旧委托未获得权限的工具默认关闭。代码默认执行前确认，草稿和媒体默认允许自动调用，发信与部署必须逐次预览确认。

Agent 可调用 `run_code`、`mail_draft`、`generate_image`、`synthesize_speech`、`send_mail`、`github_deploy`，并通过 `read_local_result` 回读交付文件。产出关联当前任务，记录文件哈希与回执；权限或内容变化会使待确认动作失效，结果未知的外部请求不会自动再次提交。

代码以当前 Windows 用户身份执行，可以访问文件和网络；独立工作目录、时限和进程树退出不构成安全沙箱。自动执行权限只应授予可信任务。图片使用所选 Codex 订阅模型，每个委托最多提交 3 张；语音使用系统安装的声音。视频生成不属于本次范围。

邮件与部署仍需先完成对应账号、目标范围和权限配置。服务受理回执不代表收件人已收到邮件或部署已成功。

## 办公连接与注册

能力中心 → 本机工具 → 外部服务注册与授权指南包含飞书、Slack、Notion、Outlook、GitHub/部署、企业微信和钉钉的官方入口及填写步骤。没有账号或目标地址时保持待接入，不创建假连接。

Slack 可选读取当前时间范围内消息的话题回复及附件。Notion 可展开子页面、数据库及可下载附件；Outlook 可读取文件附件，并通过自注册公共客户端设备码登录、自动续期。密码栏中的令牌和 OAuth 刷新令牌由本机凭据库保护。

附件限每个 10 MB、单页总计 30 MB、20 个，支持文本、PDF、DOCX 和常用图片；未支持的类型会明确提示。Notion 展开限 12 层、100 次请求、49 万字符，超过限制保留原来源。Slack 更早话题的新回复、平台历史删除、Notion 被截断的长属性和 Outlook 链接/邮件型附件仍须核对；此构建不是外部账号全量备份工具。

企业微信/钉钉需组织管理员创建机器人；仅接收获准机器人消息。个人微信全部历史同步未提供。企业数据平台仍需组织自己的 Windows CLI 与登录，无法由通用安装包代办。

## 验证范围

`test:windows` 自动发现上游运行时测试并加入 Windows 原生测试，不再只运行少量关键用例。实际测试覆盖：

- 任务与项目、Agent 推进和并行、权限、预算、恢复、材料追溯、验收与交付等业务规则。
- Windows Job Object 子进程和后代进程退出、飞书固定账号、临时配置 ACL、版本与配置篡改拒绝。
- 原生 EXE 和 npm CLI 适配、订阅 CLI 中文输入输出、Python 与 Git 仓库能力。
- 中文图片、带 EXIF 方向的 JPEG、扫描 PDF 本机 OCR。
- 实际 Windows 控件划词、点击后复制、原剪贴板恢复、密码控件拒绝、鼠标框选与截图像素。
- 实际打包 EXE 的启动、原生组件加载、快速收集、无模型保存、冷启动持久化，以及通知快捷方式身份写入和回读。

上游 macOS 安装包、签名和私有历史发布门禁单独保留，不算作 Windows 已通过。需要文件符号链接权限的个别夹具会明确标记跳过；目录链接使用 Windows junction 实测。具体运行结果、跳过数量和包内哈希见交付的验证报告及 `WINDOWS_PARITY.md`。

Windows OCR 没有暴露识别置信度，记录中的 0 表示未知。文件写入保留内容 fsync 和原子替换；Node 在 Windows 无法 fsync 目录句柄，突然断电时目录元数据持久性由系统决定。

## 源码构建

开发验证需要 Node.js 24+、Git for Windows、Python 3、Windows .NET Framework 4.8 和 OCR 语言组件。应用基础运行本身不需要安装这些开发工具。

```powershell
npm ci
npx playwright install chromium
npm start
npm run test:windows
npm run windows:package
```

`windows:package` 构建前端和 C# 系统组件，运行完整 Windows 回归，生成免安装程序，逐文件校对应用源码与 ASAR 哈希，再从独立临时工作空间启动实际 EXE。结果位于 `release-windows/<时间>/`。测试中的桌面控件用例会短暂打开合成测试窗口。

第三方服务配置与完整工作流程见 `USER_GUIDE.md`，功能和验证对应表见 `WINDOWS_PARITY.md`。
