# 查看成果与作出决定

从 v0.24.11 起，「工作产出」按事项展示，每项先放当前成果，再显示需要你处理的决定。侧栏数量只统计当前成果，历史记录另计。

## 推荐操作

1. 打开「工作产出」，点击「当前成果 · 先看这份」。多份当前成果会保留并分别显示。
2. 查看「交付范围与检查结论」，注意未验证部分及已知缺口。
3. 点击「核对并验收」，对照完成标准，选择「已阅读，验收该成果」。
4. 不符合要求时点「提出修改意见」，填写遗漏或修改要求后提交。系统沿用现有 Agent 推进、暂停和额度规则。

「待我决策」和事项详情也能直接查看当前成果、打开验收要点或提出修改。

## 版本和验收依据

当前成果必须由本事项现行执行步骤明确引用，且步骤已经完成、正文存在、事项和步骤关联一致。重新规划或取消后，原文稿只保留在历史记录中。不会因为文档名字包含“最终版”或时间较新就把它认作当前稿。

多份当前成果中，优先显示已有成功交付且回读确认的文稿；没有此类回执时，优先显示最后一个已完成文字步骤的成果，其他当前成果仍可见。

「历史版本与过程稿」默认收起。打开历史稿时会显示版本提示，可直接跳转到当前稿。历史内容不会删除。

“待你验收”沿用后台对当前材料、步骤、检查、回执、依赖和未解决问题的校验。依据变化时，不再显示为可验收。页面复用未变化数据的检查结果，实际提交验收仍重新校验版本。

保存回执代表写入当时已经核对，不表示页面实时检查磁盘文件。App 的检查通过也不替代用户对业务适用性和未验证部分的判断。

展示和验收不调用模型。验收后，符合已有托管条件的委托可能继续最终目标检查。

交接文档中的 Markdown 表格按列显示，支持行内代码、加粗和单元格换行。超宽表格可横向滚动；导出的原文内容保持完整。
