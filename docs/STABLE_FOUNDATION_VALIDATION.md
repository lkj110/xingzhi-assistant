## 仍未通过的四项

1. `long-generation` 的子进程活动测试：显式设定 200 ms 空闲窗口，原测试及定向复测仍超时。另行离线诊断中，同一 Windows 子进程包装器首次输出为 217.7 / 240.9 / 226.4 ms；实际产品默认空闲窗口为 15 分钟。诊断支持启动延迟超过测试预算的解释，但没有定位原失败的完整因果，**不是原测试通过，也不证明在线模型当前可用**。未改生产策略或测试断言。
2. `p1-b2-lark-identity` 的 `abort-transient-probe`：等待合成子进程就绪超时。属于飞书连接器进程组恢复场景，原因未定位，不写成已修复的环境问题。
3. `system-controlled-worker` 的 `full-delivery check-revise`：60 秒超时。属于完整 Agent 自动交付链，原因未定位。
4. 同套件的上下文授权修复跨重启检查：`observation timeout`。属于完整 Agent 的上下文授权恢复，原因未定位。

原来的外部写入回执 `uncertain`/`done` 断言在不改条件的定向复测中通过；原始失败仍保留。其余三项涉及测试前已排除的连接器/完整 Agent 自动链，不能以基础闭环成功抵消。它们阻止完整功能通过，不被列为本版已验收能力。
