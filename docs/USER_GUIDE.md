# 行知助手使用说明

适用于 v0.42.4 源码。现有 GitHub latest 安装包仍为 v0.40.0，本次不新建 Release/资产；旧包不保证具备下述新能力。本文随 App 内置，可离线阅读和下载。先完成一个小目标，再逐步配置长期托管。

## 快速上手

**第一次使用，按四步完成一件小事。**

1. 连接模型：打开「模型与设置 → 模型配置」，添加模型并测试连接，为信息整理、事项推进、结果检查选择模型。三个角色可以使用同一个配置。
2. 记录事项：点「新建事项」，只需贴一段话，再点「创建并交给 Agent」。Agent 自动填写标题、背景、目标和步骤，并继续推进。未连接模型时会先引导配置，选择「暂不配置，手动创建」才进入人工表单。
3. 查看进展：打开「Agent 委托 → 委托列表」，查看下一步、已有产出和运行记录。缺少信息时补充材料；需要判断时到「待我处理」。
4. 验收结果：打开「工作产出」，先看标为「当前成果 · 先看这份」的文稿。符合要求后核对并验收；不符合时提交修改意见，让原 Agent 继续。

**可直接照着填写的例子：**

- 文字材料：本周已完成需求评审；接口联调延期至周四；周五需要向项目组同步进度。
- 希望推进什么：整理本周项目进展，并列出下一步。
- 预期结果与推进要求：输出一页周报，分为已完成、风险、下一步；缺少负责人时标注待补充，不编造；先生成草稿供我验收。

阅读上手说明不会创建事项、开启自动工作或调用模型。关闭弹窗后，下次启动不再自动显示；可在使用说明中点「重新查看上手引导」。

## 页面导航与工作流程

| 入口 | 主要内容 | 适合什么时候打开 |
| --- | --- | --- |
| 工作台 | 工作看板、今日安排、工作简报、推进记录 | 看整体进度和当天安排 |
| 待我处理 | 待我决策、成果验收、关注提醒 | 补范围、批动作、验收结果 |
| Agent 委托 | 委托列表、工作规则、工作方案 | 把目标交给 Agent，或配置重复工作 |
| 信息收集 | 信息收件箱、信息连接、收集队列、材料归类 | 导入材料、接入来源、处理失败 |
| 项目 | 全部项目、工作地图、工作记忆 | 长期积累背景并管理相关事项 |
| 工作产出 | 当前成果、检查结论、历史过程稿 | 找到该读的文档并决定是否接受 |
| 全局检索 | 材料、事项、成果、决定等 | 找回以前的信息 |
| 模型与设置 | 模型配置、能力中心、运行与恢复、工作体检、使用说明 | 配置与排查问题 |

**项目**保存一个长期目标的背景与材料；**委托**是交给 Agent 的目标和权限；**事项**是可以推进与验收的工作单元；**步骤**是事项内部的行动；**成果**是实际生成的文稿或文件。

通常的流程是：收集材料 → 建立或更新事项 → 推进步骤 → 检查成果 → 人工验收。新材料会尽量归并到对应项目与原事项，遇到归属冲突会等待你判断。

## 快速新建、补充与来源追溯

在其他应用选中文字后，窄工具栏提供「新建事项」「补充事项」「智能归类」。需要允许辅助功能。文本编辑、飞书等应用直接读取选区；Sublime 等未提供选区接口的编辑器使用兼容模式。截图可用 ⌘ ⇧ 2 框选，或把截图粘贴到快速收集小窗。无法读取选区时，可复制文字，再从托盘打开小窗。

1. **新建事项**：选择「新建事项」，补充预期结果（可选），点「新建并推进」。Agent 根据材料填写背景、目标和步骤。
2. **补充已有事项**：选择「补充已有事项」，选中目标，贴文字或加入截图，再点「补充并继续」。也可在事项详情的「关联材料」点「快速补充文字或截图」，直接带入目标事项。
3. **智能推荐**：文字、文件和截图识别文字在本机与推进中的事项匹配；依据包括相同任务编号、来源链接、标题和共同关键词。推荐会显示原因，不消耗模型 token。多个事项相近时需手动选择；也可随时改选新建。只有点击提交后才保存关联。
4. **记录来源**：自动记录采集方式、时间，以及能读取到的应用、窗口和网页地址。系统未提供的信息不会猜测；可以填写来源链接和说明。截图保留文件名、识别文字及定位信息，不承诺还原原始图片。URL 去除登录凭据、token 等认证参数和片段，保留用于定位原文的普通查询参数。
5. **查看补充记录**：事项「关联材料」可打开原文和来源；事项备注、收集队列保留补充记录。重复文字复用原材料，并保留再次采集的来源时间。

补充会让 Agent 重新核对受影响的计划与成果，原成果仍保留。继续原委托时沿用工具权限、调用记录和累计费用上限；补充材料不会回答需要你选择的问题，也不会解除暂停或费用限制。「仅补充材料」维持原委托的运行或暂停状态；已开启的持续工作仍可按原计划使用新材料。

已完成、取消或归档的事项不在候选中。旧版独立推进且已有费用记录的事项可以补充材料，但需从事项详情沿用原推进方式，以保留原累计额度。未配置模型时仍可仅补充；选择继续会先引导配置模型。

## 连接模型与订阅

入口：**模型与设置 → 模型配置 → 添加模型**。

先选择「服务商预设」，填写该服务的 API Key，然后点「读取模型列表」或直接填写模型 ID。模型 ID 不设白名单，因此服务商的新模型、聚合平台模型和自部署模型都可以自行填写。读取列表只查询模型目录，不进行推理；部分服务不提供目录，此时手动填写即可。

| 接入方式 | 服务与模型 | 配置要点 |
| --- | --- | --- |
| 国内服务预设 | DeepSeek、Kimi / Moonshot、通义千问 / 百炼、豆包 / 方舟、智谱 GLM、MiniMax | 预设填好协议和常用地址，模型 ID、密钥、区域或套餐地址以自己的账号为准 |
| 国际服务预设 | OpenAI、Claude、Gemini、Azure OpenAI、xAI / Grok、Mistral | 支持 Chat Completions、Responses、Anthropic Messages、Gemini generateContent；Azure 填部署名 |
| 聚合平台 | 硅基流动、OpenRouter、Groq、Together AI | 填平台返回的完整模型 ID，可接入平台提供的开源模型；列表可能包含非文本模型，需选文本对话模型 |
| 本地与自建 | Ollama、LM Studio、vLLM、SGLang、llama.cpp 或兼容网关 | 先启动服务并加载模型，填写实际端口与服务中的模型 ID；DeepSeek、Kimi、Qwen、Llama、Gemma 等权重是否可运行取决于外部服务和硬件 |
| ChatGPT / Codex 订阅 | 本机可用的 Codex CLI 和已登录的 ChatGPT 账号 | 按界面检测登录及填写可用模型，无需在 App 填 API Key |

### DeepSeek、Kimi 与开源模型

- 直连 DeepSeek：选择「DeepSeek」，填写自己的密钥，读取模型列表或填写账号可用的对话 / 推理模型 ID。
- 直连 Kimi：按账号选择国内或国际入口。填写模型 ID；如果使用推理强度等专用参数，在「高级生成参数」中按该模型文档填写。
- 使用托管开源模型：选择硅基流动、Groq、Together AI 或 OpenRouter，填写该平台的完整模型 ID，而不是随意填写权重名称。
- 使用自部署模型：选择 Ollama、LM Studio 或 vLLM / SGLang / llama.cpp。模型由外部服务下载、加载和运行，行知负责调用，不自带模型权重。

保存后点「测试连接」，成功后为「信息整理」「事项推进」「结果检查」选择配置。测试会实际调用模型并记录用量。工作数据保存在本机，使用远端模型时，本次任务所需文本会发送给你选定的服务。

### 高级接口设置

- **接口类型**与**服务商**是不同概念：DeepSeek、Kimi 等可使用 OpenAI 兼容协议，并不意味着请求发往 OpenAI。所有请求发往界面配置的服务地址。
- **服务地址**可自定义代理前缀、区域地址或完整生成端点；不要在 URL 中放密钥或查询参数。Azure 旧版 API 的版本单独填写，推荐使用资源的 `/openai/v1` 地址。
- **鉴权方式**默认按协议选择，也可改为 Bearer、x-api-key、x-goog-api-key、api-key 或无需鉴权。Claude 跨工作空间密钥可填写工作空间 ID。
- **JSON 输出模式**：不支持原生 JSON 模式的模型可取消勾选，行知仍会校验工作协议中的 JSON。Claude 使用提示词约束 JSON。部分预设默认关闭原生 JSON，以兼容同一平台上的不同模型。
- **最大输出 token**：留空使用服务默认值；Claude / Anthropic 兼容接口默认 8192。部分推理模型需要 `max_completion_tokens`，可在兼容接口中切换。上限也可能包含推理 token；被截断的结果不会作为成功的完整产出。
- **高级生成参数**：填写 JSON 对象，例如 `{"reasoning_effort":"high"}`、`{"thinking":{"type":"enabled"}}` 或 `{"enable_thinking":true}`，只使用该模型文档明确支持的参数。Gemini 参数写入 `generationConfig`，Ollama 写入 `options`，其他协议写入请求体。不能覆盖消息、工具授权、模型、输出格式或输出上限，也不能填写密钥。
- **费用**：API 价格按服务商、模型、地域和套餐填写。缓存命中与推理用量按接口报告记录；Claude 的缓存写入区分短期与 1 小时折算，实际计费仍以账单为准。远程收费 Ollama 应填写实际单价。

订阅权限取决于本机登录与账号可用模型；App 不把订阅转换成 API Key。切换预设会清空旧模型与密钥，修改服务域名或端口后须重新填写对应服务的密钥，防止误用旧凭据。桌面密钥加密保存，导出工作空间不包含密钥。

本次扩展覆盖**文本生成与推理模型**。图像生成、音视频生成、嵌入、重排模型和专有云 IAM 签名接口不属于这些聊天协议；Bedrock、Vertex 等专有接口需要先经支持上述协议的网关接入。接口可接入不代表每个模型都能可靠完成 Agent 工作，应先测试连接，再用小任务验证效果。

## 自动选模、等待与故障接续

入口：**模型与设置 → 模型配置**。

- 自动选择模型：指定「日常模型」和「分析模型」后保存启用。工具调度、提取、精简已有内容和日常跟进优先用日常档；血缘、根因、多来源对比等复杂分析使用分析档。
- 单个事项：在事项详情的「模型选择」中覆盖自动选择，或固定使用角色模型。
- 两档选了同一配置，就不会出现不同模型的运行记录。实际选择及原因可在调用详情核对。
- 等待与重试：每个模型可以设置「无新数据等待」和「总等待上限」。0 表示不限时；默认总时长不限，不是固定四分钟。模型长时间思考也可能没有新数据，应按任务调整。
- 故障接续：按配置对超时、网络或临时服务错误重试；启用备用模型后使用配置的备用项。鉴权失败、额度耗尽等问题需要先处理。重试与备用调用都消耗同一推进额度。

自动选模只在你保存并选择的配置中工作，不会自行购买模型。选择两档时应核对各服务的实际定价。

### 节省重复消耗

- 规划、执行、最终检查默认只携带当前步骤的成果。历史版本保留标题和 ID，Agent 需要时可按 ID 读取；执行资料以当前事项引用的来源及最近检索证据为准。
- 日常生成使用来源节选，血缘结构索引保留全部节点和关系；资料不足时继续读取，不能把节选当作全部证据。最终核验保留更完整的证据范围。
- 长短文稿都可按准确片段局部修改，未修改部分原样保留。自动模式下精简、润色等编辑任务一次生成；显式选择「按章节生成」仍按你的设置执行。
- 本次修改意见只涉及精简、润色等文字编辑时使用已配置的日常模型。复杂分析和关键验收仍按完成标准选择分析模型，事项手动选模优先。
- 检查通过后保存片段指纹。要求、来源和依赖未变时，复用位置、标题与内容均未变的片段检查，重新检查改动、相邻内容及整体要求。证据或要求变化、原检查失败、旧版没有检查记录时，执行完整检查。模型无法确认影响范围时会自动重新读取全文检查。
- 事项「结果检查」显示本次是否复用；每次模型调用依旧分别记录 token 与折算费用。

## 快速记录、选中文字与截图

入口：顶部 **快速收集**。主窗口快捷键为 **⌘⇧I**；全局快捷键 **⌘⇧空格** 需在「桌面快速收集」开启。

小窗默认只需 **文字材料或文件**，选择新建或补充，再点击「新建并推进」或「补充并继续」。Agent 自动整理标题、背景、目标、完成标准和执行步骤，然后继续产出与检查。「补充目标、预期和能力」为可选项，标题与所属项目也可展开补充。

未配置模型时会先提示连接；去主窗口保存模型并补齐三个角色后，本次提交自动继续，草稿会保留。选择「暂不配置，仅保存材料」后，可先把内容留在收件箱。主窗口「新建事项」则提供完整的人工创建表单。

已配置模型时不需要再建立委托或点击「推进下一步」。助手忙碌会自动排队，退出后重新打开可接续。全局托管暂停、工作时段和额度限制仍然有效；遇到关键缺口时会请你补充，最终成果停在待验收。

| 按钮 | 效果 |
| --- | --- |
| 仅保存 | 保存材料，之后再整理 |
| 保存并整理 / 识别并转事项 | 导入材料并整理；图片先在本机识别文字 |
| 新建并推进 | 从原文自动整理新事项并持续推进，结果等待你验收 |
| 补充并继续 | 把新材料关联到选定事项，沿用原委托继续 |

以下两项默认开启；可在「信息连接」或「模型配置」中的「桌面快速收集」关闭。首次使用及升级后会显示权限说明，点击「授权辅助功能」到系统设置允许行知助手；返回后会自动检测，无需重复开关。

- 选中文字弹窗：在 macOS「隐私与安全性 → 辅助功能」允许行知助手后，鼠标或键盘选中文字会出现一行窄工具栏。可选择「新建事项」「补充事项」或「智能归类」，在小窗核对目标、补充预期后提交；未配置模型时，选择推进会先引导连接。工具栏为 288×38 像素，没有关闭按钮。点击工具栏外、取消选区、滚动、继续输入、按 Esc 或切换到其他应用会自动收起；再次划词会重新出现。展开后的录入窗口仍有关闭按钮，关闭后保留草稿。Sublime 等应用不提供可读选区时，在编辑区拖选或双击会先显示工具栏，点击操作后通过应用的复制命令读取选中内容，并恢复原剪贴板。未点击时不读取剪贴板，不调用模型。读取失败时可手动复制后粘贴；新选区、窗口切换或超时后请重新选择。
- 截图快捷入口：默认开启，按 **⌘⇧2** 框选屏幕，完成后带入小窗。首次使用按系统提示处理屏幕录制权限，也可点「框选截图」或粘贴剪贴板图片。
- 系统自带截图：复制后在小窗按 ⌘V 粘贴。App 不会自动截取所有系统截图，也不持续读取剪贴板。

选区在提交前只作本机预览。窄工具栏随选区自动收起；展开后的录入窗口点击“×”会关闭窗口，不关闭划词功能。隐藏的旧草稿不会阻止下一次浮窗；再次捕获时会提示保留的草稿，选择加入或忽略新内容，不自动覆盖或提交。正在编辑的小窗会暂缓浮窗，关闭后即可继续划词。隐藏窗口保留草稿，退出 App 会清除尚未提交的草稿；已入队材料保存在本机。

点击「新建并推进」或「补充并继续」后，材料安全入队即自动收起小窗，App 在后台处理，不会自动打开主窗口。保存失败时保留草稿和错误说明；后续处理失败可在「信息收集 → 收集队列」重试。再次划词可以记录下一条信息。

新建事项和快速记录均直接展示「本次使用的仓库与扩展能力」。默认不勾选，Agent 仅使用已配置模型和提交材料，不会自动使用能力中心中的仓库。勾选一个或多个能力后，本次推进可按需调用；点击「不使用，清除选择」可撤销选择。每次调用按仓库的本地或远端更新设置读取最新内容。

补充已有事项、或指定已有委托/规则的项目时，会显示沿用的能力名称，并保持原委托与累计额度；暂停中的委托保持暂停。需修改能力时到原委托的「扩展能力」更新授权。新项目尚无委托和规则时，可直接选择本次能力。快速记录本身不自动授予其他文件夹、网页或外部写入权限；需要更广资料范围时在委托中配置。

## 材料导入、识别与收集队列

入口：**信息收集 → 信息收件箱 / 收集队列**。

普通导入窗口与快速记录小窗都会保留每个文件自己的来源；后台忙碌时进入队列也不丢失。截图保留采集时间与方式，带来源的文件保留其应用、标题、链接等可用信息。相同正文再次录入可复用材料，并追加采集来源；来源说明不等于额外的数据访问授权。

快速小窗中手动修改的来源链接和说明用于本批所有材料（包括只上传文件的情况）；未修改的字段仍保留各文件自己的来源，不自动复制文字或其他文件的来源。清空字段会移除该字段。已保存的历史来源不会被追溯重写。

支持手动输入、粘贴、拖放或选择 TXT、MD、CSV、JSON、PDF、DOCX、PNG、JPG、JPEG。Word 请使用 DOCX。每批最多 10 份文件、每份 10 MB；快速收集本批总大小最多 25 MB。

- 文本提取最多 50 万字符；PDF 最多 250 页。较长材料可按页码、段落检索。
- 图片在本机识别中英文，单张边长最多 10,000 像素、总计最多 2,500 万像素。识别可能漏字或误读，应核对姓名、数字和任务编号。
- 扫描 PDF 最多识别 20 个无文字页；有文字页内的图片不会额外识别。OCR 后的文本可发送给选定模型；图片和 PDF 原文件不上传给模型。
- App 忙时，材料先进入队列。队列显示阶段、错误、关联材料及对应委托；失败后可以重试。
- 「临时服务故障自动重试」仅适用于保存并整理，需主动开启，最多三次。记录并推进的后续执行遵守委托自身的规则。

点「整理并拆解」会调用整理模型。只导入或同步材料不等于已经完成工作，需检查对应事项或委托是否已启动。

## 主动收集与长期托管

入口：**信息收集 → 信息连接 → 配置主动收集**，或 **项目 → 新建托管项目**。

1. 填项目名称、目标、预期结果和初始材料。
2. 选择公开网页、RSS、授权本地目录、飞书文档或会话，设置关键词和检查间隔。
3. 选择允许使用的能力、产出位置和推进规则。
4. 核对预览；需要自动执行时勾选「创建后启用资料收集和推进规则」，再保存。

后续来源更新会归入原项目，沿用原事项和委托。没有变化的检查不调用模型；有变化后按规则推进。来源过滤、全局暂停、工作时段、累计费用上限仍然生效。

以暂停状态创建时，来源和推进规则都保持暂停。只配置收集来源而没有项目委托时，材料会先保存。连接页会显示实际启用情况、最近检查和当前阻塞原因。

## 办公与聊天工具

入口：**信息收集 → 信息连接**。各来源先选择归属项目，再配置登录或凭据。

| 来源 | 当前可读取内容 | 使用边界 |
| --- | --- | --- |
| 飞书 | 指定文档 / wiki、指定会话的文字消息 | 使用本机 lark-cli 用户登录；不自动读取全部会话 |
| 企业微信 | 发给指定智能机器人的新文字消息 | Bot ID + Secret，长连接模式；不读取员工完整会话历史 |
| 钉钉 | 发给指定机器人的单聊或群内 @ 消息 | Client ID + Secret，Stream 模式；不读取全部群聊历史 |
| Slack | 指定频道 / 会话的主消息 | 对应 history 权限；未覆盖完整话题回复与附件正文 |
| Notion | 指定页面的嵌套文字、表格与待办状态 | 共享给集成；不展开子页面、数据库或下载附件 |
| Outlook | 指定邮件文件夹的邮件正文 | 全球版 Graph 用户委托令牌；过期后手动更新，未接入附件和内置 OAuth |
| 通用 JSON | 已授权采集服务提供的 HTTPS 消息流 | 格式示例见配置页；通过稳定 ID 去重与更新 |
| 个人微信 | 主动提供的截图、复制文字或导出材料 | 尚未接入账号自动同步 |

飞书按配置指引完成 CLI 登录后，在对应连接中预览并确认采集账号、租户和范围，再开始同步。旧连接首次升级需明确绑定，已有材料和历史断点会保留。文档填完整 /docx/ 或 /wiki/ 地址，会话填 oc_ 开头 ID。消息增量读取，并回看最近 24 小时的编辑；更早修改、完整话题回复、附件和表格未完整覆盖。

持续采集固定使用该连接确认的账号。确实要换账号时，在连接中重新预览并绑定；新账号使用新的同步窗口，不沿用旧账号的游标。已撤回采集或本地读取许可时，普通保存、开关和重试不会重新授予。当前固定身份适配经过 CLI 1.0.65 的协议核对；组件不支持、凭据不可用或身份核对失败时，连接会显示具体阻碍并停止采集，不改用其他账号。

材料的本地保留与读取权限分别检查。撤回读取后，项目简报、材料全文检索和事项推荐都不再使用该正文及来源链接；仅保留文件不代表仍允许这些用途。已在撤权前导出或下载的副本不会被远程收回。

企业微信与钉钉要求 App 运行且允许自动工作；退出、休眠或暂停期间可能漏收，平台不保证补发。收集入口不自动发送聊天回复。发送消息须另行配置对应支持渠道的授权。

## 网页、RSS、本地目录与 GitHub

入口：**信息收集 → 信息连接**；Agent 的工具与目录设置在 **Agent 委托 → 工具与连接**。

- 网页连接：定时检查指定公开页面，保留新版本。需要登录、动态渲染或受限页面可能无法完整读取，应补充可访问材料。
- RSS / Atom：订阅指定信息源，按关键词与项目规则过滤、归并；在连接页查看新增、跳过和失败原因。
- 本地目录：由你选择允许同步或读取的文件夹，按支持的文件类型收集。检查文件变更和撤回后，在材料版本中核对影响。
- GitHub：委托填写 owner/repo 和允许操作范围。私有仓库及写入操作需适当 Token 权限；只授权指定仓库。创建 Issue、更新及评论各有策略和限额。
- 网页搜索：自主搜索需配置 Tavily Key；直接读取给定公开网址不需要搜索 Key。

这些来源不会自动获得无限访问权限。来源不可用时，查看错误并补登录、路径或材料；不要把读取失败当作没有相关信息。

## 委托 Agent 推进事项

入口：**Agent 委托 → 委托列表 → 新建委托**。

「委托类型」默认是完成本次目标后结束；需要长期追踪时选择「持续跟进来源变化」。一次性委托在最后一项验收时一并关闭；持续委托在一批成果完成后等待新信息。委托列表默认显示进行中，可切换「已完成」或「全部」查看历史。

写清目标、资料范围、预期产出、验收标准和已知约束。例如：「梳理给定六个入口的全部可访问上下游；筛出本人负责的任务；以最终对外输出节点为核心写一页交接说明；无权限节点列为缺口。」

再选择参考网址、本地目录、能力、产出目录、执行权限、检查间隔和调用次数上限。提交后，Agent 可在授权范围内获取资料、建立或更新事项、生成成果并跟进。

需要梳理 SG 数据任务时，可在委托表单勾选「允许读取 SG Dorado 与 Coral 元数据」。此能力使用本机已登录的 bytedcli，查询账号、任务、SQL、产出表及上下游，保存查询快照；不执行 SQL，也不修改平台任务。请写清入口与“本人任务”的范围。无权限、跨区域或尚未查完的分页应保留为缺口，不可当作链路结束。

- 委托详情先看当前状态、下一步和需要你的输入，再看运行记录。
- 已有事项可从详情交给 Agent；修改原结果时优先沿用原事项和原委托，避免另起一条丢失上下文。
- 手动推进一轮只处理本轮允许的步骤；持续托管依赖启用状态、工作时段、资料和预算条件。
- 缺少业务事实时补充材料或范围。Agent 的推测不能替代真实来源、外部执行回执或人工验收。

## 看板状态、依赖与跟进

入口：**工作台 → 工作看板 / 今日安排**，或打开事项详情。

| 状态 | 含义 | 你可以做什么 |
| --- | --- | --- |
| 待推进 | 已有目标，准备处理下一步 | 补充要求、交给 Agent 或手动推进 |
| 正在推进 | 当前正在生成或检查 | 查看进度，需要时停止本轮 |
| 等待反馈 | 等待外部动作、回复或跟进时间 | 补充真实反馈，设置或检查跟进安排 |
| 需要关注 | 缺资料、权限、依赖、预算或发生错误 | 查看具体原因，处理后重试 |
| 待验收 | 产出与检查已准备好 | 阅读当前成果，接受或提出修改 |
| 已完成 | 已通过对应验收流程 | 查看结果；新要求可按原流程继续修改 |
| 已暂停 | 暂不执行 | 核对范围后主动恢复 |

事项依赖前置任务时，先处理依赖；工作地图可查看关系与阻塞。单个事项等待补充不应挡住同一委托中不相关的可执行事项。

新设置的明确截止时刻默认在提前 24 小时、提前 1 小时和到期时提醒；历史安排保留原来的提前 24 小时及到期提醒。仅填写日期时保留日期，不把它当作零点截止。提醒可确认或稍后处理；暂停自动托管仍可提醒，但不会借截止时间解除暂停、权限或费用限制。App 退出或休眠时不能发通知，返回后按当前阶段补一次，不重复补发错过的所有阶段。

「今日安排」可筛选项目和日期、批量调整优先级或截止时间，也可导出 .ics 日历安排；日历文件需要你导入自己的日历，App 不会直接改写外部日历。

外部执行步骤需要实际回执。若动作由你完成，在事项中填写真实结果，再继续检查；不要仅凭模型生成了一段“已发送”文字就认定发送成功。

## 删除与恢复事项

- **删除：**打开事项详情，在状态旁点击「删除事项」，核对影响后确认。
- **恢复：**工作台顶部二级导航 →「已删除」→「恢复事项」。恢复后保持暂停，核对后再恢复推进。
- 删除后事项从看板、今日安排和快速补充候选中移除，停止提醒和推进；材料、历史成果、执行记录与费用保留。
- 有关联 Agent 委托时会暂停整个委托，作废尚未执行的确认。依赖此事项的其他事项需重新核对计划；你可在委托中说明新范围后恢复。
- 正在执行时，请先停止本轮或等它结束；外部动作结果未知时，请先核对实际结果再删除。
- 待处理的补充材料保留并停止自动重试，恢复事项后可手动重试。恢复事项不会重新启用旧确认或跟进安排。
- 已删除事项的成果仍可在「工作产出」中查看，标记为历史记录。恢复旧备份或撤销项目归并不会撤销你后来作出的删除或恢复决定。

## 成果阅读、验收与修改

入口：**工作产出** 或 **待我处理 → 成果验收**。

1. 先看顶部的最终交付：要求转成飞书时直接打开飞书文档，GitHub 事项显示实际链接，本地文件显示文件名和所在位置。尚未要求外部交付的文稿继续直接阅读当前成果。
2. 阅读「交付范围与检查结论」，重点看缺口、未验证部分和实际完成标准。
3. 满足要求时点「核对并验收」，阅读后确认。
4. 不符合时点「提出修改意见」，写明要删减、补充、纠正的内容及预期结构。系统沿用原 Agent、暂停规则和累计额度继续。

例如：「正文压到一页；先列三个对外输出节点和负责人；完整血缘放附录；权限缺口单独列出。」比“再优化一下”更容易验收。

已完成外部交付的 Markdown 收在「本地底稿」，辅助材料、检查报告、其他交付位置和历史版本分别折叠保留。待验收、工作产出、事项详情和待处理卡片使用同一结果入口。

最终入口依据当前计划和对应主稿的实际交付回执确定，不从模型文字提取链接，也不按文件名是否含“最终版”判断。正文更新后尚未重新发布、交付未完成或写入结果待核对时，会显示交付状态，不把旧链接当成本次最终成果。回执说明交付时已回读，不表示持续实时检查远端或磁盘文件。

验收页面本身不调用模型。最后一项验收前，App 先完成当前版本的整份委托检查；确认验收后同时关闭一次性委托。旧版本已验收但缺少整体检查的委托显示「收尾待检查」，暂停时提供「恢复收尾检查」。已完成事项的历史记录会保留，新的修改要求通过补充或编辑明确重开。

「成果验收」可按项目筛选并批量验收符合条件的事项。先逐项核对当前版本；材料、步骤或依据变化时，需要刷新后重新检查。

## 决策、外部动作与交付

入口：**待我处理 → 待我决策**，以及委托详情中的执行与交付记录。

需要补范围、解决冲突、确认外部动作或处理预算时，App 会集中显示决定。先看目标、准备执行的内容、影响范围和实际结果，再批准或提出修改。

本地写入、GitHub 创建 / 更新 / 评论、支持的消息发送各自有授权策略。选择“每次确认”时，Agent 先准备可审阅内容；批准后才执行。自动执行也受指定目录、仓库、会话、次数与间隔限制。

工作产出可阅读和下载；配置交付目录后，委托可按授权把成果写入文件，并保存执行回执。交付包用于汇总需要带走的内容，应核对当前版本和范围后再分享。

项目详情中的「项目成果交付包」可预览文件清单，选择是否包含未验收草稿及当前材料正文，再导出 ZIP；正文可能包含业务资料，分享前核对所选范围。

外部写入会分别保存发起记录、回执和回读结果；工作空间保存中断后优先恢复这些事实。交付回读属于核验材料，自身产出不会自动成为新的业务要求。来源归属不明时，可在待处理入口选择作为输入、仅作观察或忽略。

遇到「结果不明」或外部执行待核对，先确认外部是否已经成功，防止重复写入或发送。恢复备份不会撤销已经发生的外部操作。

## 工作规则与工作方案

入口：**Agent 委托 → 工作规则 / 工作方案**。

工作规则决定什么时候开始一轮工作：按定时安排、材料变化或已有配置触发，并指定目标、来源与能力。每个委托沿用累计费用上限。先预览规则，再选择启用；暂停规则会停止其自动触发。

工作方案保存常见工作的处理方式。选择方案、填写本次参数，再核对资料与执行授权后创建委托。可以从已有成果整理适合复用的方案。

方案不是已经完成的事项，保存方案本身不会代你执行。规则管理的委托在规则中调整授权；独立委托可以在详情调整。

## 项目、材料归类与工作记忆

入口：**项目**，以及 **信息收集 → 材料归类**。

- 项目背景：保存长期目标、范围、关键事实和约束；新材料与补充要求归入同一项目。
- 材料归类：设置明确的归属规则，预览匹配结果。冲突材料先确认归属，再进入后续推进。
- 材料版本：查看新增、修改、撤回及受影响事项。归并记录可核对和撤销最近支持撤销的变更；撤销后委托暂停，外部产出与用量保留。
- 信息连接中的远端标题修订也属于资料变化，即使正文未变也会形成可追溯的新版本；重复同步同一标题和正文不会不断制造版本。同一页对同一远端对象给出冲突版本时，整页拒绝且保留原游标，纠正连接器响应后再同步。
- 项目报告区分历史已验收、当前检查有效、人工执行证据与待核对。背景、来源或产出变化后，历史验收仍保留，但旧检查不再算作当前通过；人工确认不表示已核对外部交付回执。
- 旧检查缺少可核对的依据时，项目报告和工作简报都显示待核对，不抹去历史验收，也不会自动重开事项。需要当前有效结论时再重新检查。
- 工作地图：按项目查看事项关系、依赖、产出与阻塞，找到影响下一步的节点。
- 工作记忆：由你确认保存常用事实、术语和偏好。项目记忆限该项目；来源失效或条目过期后停止使用。记忆变化会要求相关未完成事项重新核对计划，但不会仅因记忆变化重新打开已完成、已验收的子事项。确实需要修改已完成结果时，请对该事项明确补充要求或重新打开。记忆不授予工具或发送权限。
- 收尾归档：在项目详情预览影响，再归档。项目的采集、推进及自动发送暂停，历史仍可查看；重新打开后按需恢复。

## 能力中心与 DW 仓库

入口：**模型与设置 → 能力中心**。

点击「添加仓库」，指定目录、填写便于辨认的名称，选择版本更新方式，点「检查能力」并挂载。可以不断添加多个仓库，通过名称和路径搜索、编辑、停用或移除；移除后仍可恢复，历史记录保留。能力中心不设仓库数量上限，每个委托最多选择 10 项。

在新委托、快速记录、主动收集向导或工作规则中勾选能力后，Agent 才能使用。已有独立委托可在「扩展能力」中更新授权。通用仓库支持 SKILL.md、AGENTS.md、README 等 Markdown 文档的目录与分页读取，Agent 根据相关说明推进；文档中提到但 App 未提供的命令不会自动获得执行权限。DW 仓库会自动识别并额外提供以下检查工具。

| DW 工具 | 当前作用 |
| --- | --- |
| list_skills | 列出技能、协议和知识文档 |
| read_document | 分页读取已登记文档 |
| sql_review | 调用仓库的 Hive / Spark SQL 静态检查器 |
| python_review | 调用仓库的 PySpark 静态检查器 |

静态检查不会执行输入 SQL 或 PySpark 作业，也不能替代生产验证。本轮未接入 DW 完整多 Agent 编排、生产 SQL 执行或发布；隔离 Python 未加载可选 sqlglot 增强。

### 仓库文档与脚本更新的区别（0.42.4 起）

文档仍按所选方式读取最新内容，无需为每次文档更新确认。DW 的 SQL/Python 检查器是可执行代码，单独选择信任策略：

- 默认只执行检查并确认过的脚本版本。脚本变化时不运行新代码，到能力中心编辑该仓库、重新检查并确认；随后按提示更新委托的能力授权。
- 可以明确选择持续信任最新脚本。此选项意味着仓库后续脚本修改也在你的信任范围；每次调用仍记录实际脚本摘要，停用或移除能力可撤回后续调用。
- 从旧版升级、尚未确认执行策略的仓库仍可读取已授权文档，但执行检查器前需要一次正式配置确认。Agent 的刷新、资料读取或委托绑定不能代你批准脚本更新。

两种策略都不是操作系统沙箱。已批准的脚本按当前用户权限运行，可能访问用户文件、网络或外部服务；App 的资料范围、联网开关及模型预算不能约束任意仓库脚本，也无法保证统计脚本自行产生的费用。Python 隔离参数只限制解释器加载环境，不提供文件/网络隔离。请只信任你能核验的仓库。

确认新执行策略后，不支持把该工作空间直接交给 0.42.3 或更旧版本运行。恢复须使用仍落实执行保护的版本，不要回滚用户数据或权限记录。

也支持本地 **MCP stdio**：填写已安装程序的绝对路径、JSON 参数数组和工作目录，检查后选择具体工具。第一版只接入声明只读且不另行调用收费模型的工具，不支持 HTTP MCP 或独立收费 Agent 的预算纳管。

只读属性来自服务声明，不是操作系统沙箱；请只挂载信任的服务。MCP 每次重新连接本机已安装的服务并校验工具定义，服务程序本身仍需自行升级。

### 每次使用最新版本

| 更新方式 | 每次调用前做什么 | 适用情况 |
| --- | --- | --- |
| 本地最新内容（默认） | 重新扫描挂载目录，包括未提交修改 | 自己维护的技能、已通过其他方式更新的仓库 |
| Git 远端分支 | 获取配置分支的最新提交，在 App 独立缓存中读取 | 希望自动跟随团队仓库更新 |

选择远端模式时需已在本机克隆仓库并完成 Git 登录；远端名和分支可留空，首次检查会确定当前跟踪分支，也可显式填写。之后一直跟随保存的远端地址与分支，切换来源请编辑能力。更新只写 App 缓存，保留原仓库的分支与未提交修改；不会自动安装依赖、执行 Git hooks 或加载子模块。无法获取最新内容时，本次调用失败，不回退使用旧缓存。失败原因在能力卡片与最近调用中查看，连接恢复后可检查更新并继续委托。

内容、版本号或提交变化且已选工具接口未变时，原委托和规则授权继续有效。新增工具不会自动加入授权；修改仓库来源、更新方式或工具范围，以及停用后重新启用，需更新委托授权。仓库脚本以当前用户权限运行，所以自动更新只适合受信任的来源。

「最近能力调用」记录实际版本号、Git 提交号（如有）、内容指纹及本地修改标记；更新不会改写历史记录。工具结果与版本信息一并保存在委托材料中。旧记录若没有版本信息，会明确标注。

## 模型用量、费用与上限

| 想查看什么 | 入口 |
| --- | --- |
| 本轮实际模型、token、折算费用 | Agent 委托详情 → 运行记录，展开逐次调用 |
| 某事项每次推进的用量 | 事项详情 → 推进用量与额度 → 每次事项推进的模型与消耗 |
| 整个推进过程累计及剩余额度 | 委托或事项详情 → 推进用量与额度 |
| 全局最近调用与耗时 | 模型配置 → 最近模型调用；运行与恢复 → 执行效率 |

合计 token = 输入 + 输出；缓存输入已包含在输入中，不重复相加。费用按普通输入、缓存输入、输出分别折算；支持缓存写入或长上下文规则时按对应价格计算。每次请求保存当时的价格，不随后续配置变化重写历史。

默认 **一次推进全过程共用 $100 等值上限**，包括子事项、规划、检查、重试、续跑与修改反馈。不限制累计模型调用次数；重启或恢复备份不重置累计值。

订阅美元值是 App 按参考单价折算的控制金额，不是订阅实际扣款或余额。第三方接口应填写自己的价格；本地 Ollama 默认模型费为 0，不含设备、电费。搜索、办公服务等其他费用不在模型 token 预算中。

请求前会预留预计费用；请求后以报告用量结算。已知费用加预留（含下一次请求）超过额度时才需要追加确认。未知用量已有预留时，沿用原上限继续；只有缺少预留的历史调用需要核对。未确认的预留不会被当作零消耗。

已配置的 HTTP 输出上限同时用于请求和费用预留；Claude 未配置时沿用 8192 默认值。其他 HTTP 接口未配置上限时仍按 128000 输出 token 估算，Codex 订阅按不低于 128000 的估算预留，不能强制 CLI 的输出长度。高级参数中的 `n`、`best_of`、`candidateCount` 仅支持数值 `1`，因为应用只处理一个候选结果。配置错误会在请求发出前提示，不会静默改写。

这是应用内控制，不是服务商账单硬上限；在途请求的最终消耗可能高于估计。请以调用详情及服务商账单分别核对。

## 超时、失败与用量未知

**超时**可能来自网络、服务响应、CLI 退出，或模型长时间没有新数据触发了等待设置。先看本次错误和已有进度，再决定重试或修改等待时间。

- 长文可在事项详情「长任务与已有成果」选择按章节生成；章节保存后，中断时从尚未完成部分继续。
- 已有草稿可按界面要求导入并继续检查。补材料或改要求可能触发重新规划，旧章节仍可下载。
- 生成已完成、检查失败时，重试会优先复用已有产出，不应另建同一事项。
- 暂停中的委托先主动恢复。缺少凭据、权限、预算或外部回执时，先处理对应原因，重复重试不能解决这些问题。

**保存提示**：若界面提示“已保存，但后续处理或刷新未完成”，先刷新并核对已有记录，不要另建相同内容。新增材料归类规则遇到回复丢失时，保留原表单核对或重试同一次请求；重复点击不会代表你想新建另一条规则。明确需要另一条规则时再开始新的新增操作。

**用量未知**常见于请求中断前未返回 usage、服务未提供字段、CLI 异常结束或旧记录缺失。它不表示请求没有执行，也不代表没有成本。App 会展示缺口并保留预留；原额度够用时继续，不逐笔要求确认；无法从字符数还原准确 token。

## 补证、草稿和最终交付

委托会区分“已取得证据”“已纳入修订、待核验”和“仍待补齐”。来源数量增加，只说明材料已保存，不表示最终文档已更新。新证据会先关联到当前事项，再用于局部修订原主稿；详情和附录仍属于同一交付。

证据尚未齐全时，修订稿会保留为草稿。只有所需证据已覆盖（或有明确接受的缺口）、当前稿检查通过，才会写入已授权的外部目标。写入后还要回读并检查，最终在成果处展示真实文档链接，等待你验收。

批量查询中部分成功、部分失败时，已保存结果会保留。网络瞬时失败、身份检查失败和本地保存失败分别恢复：完整响应已经保留的本地错误，优先使用原响应重新保存；不能确认请求是否执行的情况，需要核对原请求，不能靠再次点击推进消除未知状态。

“用量未知”与“请求结果未知”不同。有效结果已保存、费用已预留时，后续新证据可在原额度内继续；如果请求可能已发出却没有可核验结果，App 会保留原记录和费用预留，显示具体阻碍。修改要求、重启或升级不会重置额度，也不会把未知请求算成未执行。

## 后台运行、工作时段与通知

入口：**模型与设置 → 运行与恢复**。

配置全局托管、工作时段和临时暂停；具体来源、规则和委托还需分别启用。看板的自动推进开关不能替代这些独立配置。

桌面 App 关闭主窗口后留在菜单栏继续工作；**退出 App 或电脑休眠时停止执行**。唤醒后合并补查到期工作，手动暂停不会自动解除。打包版可选择登录电脑时启动。

关注提醒集中展示新进展、阻塞和待处理决定；桌面通知受系统通知权限影响。今日安排可管理截止时间、跟进时间及支持的日历导出；工作简报可查看一段时间的实际进展并配置简报安排。

提醒可标记已读或稍后提醒，这只管理阅读状态，不代表批准动作或完成事项。「工作简报」可按项目、时间筛选并导出；启用定时保存时选择简报目录和安排，唤醒后只补存一份当前简报。

需要暂时停下时可停止本轮，或在托管控制中暂停自动工作。停止模型调用不能撤销已经执行成功的外部动作。

## 数据、备份、导出与分享

入口：**模型与设置 → 运行与恢复 → 本地备份与恢复**。

有保存操作时每小时自动备份，保留最近 30 份；也可点「立即备份」。恢复前先预览，并另存当前状态。恢复会暂停自动工作，保留较新的执行记录和当前授权；外部文件、GitHub 或消息不会回滚。

工作空间导出适合留存和检查，不含模型密钥；本机备份包含加密配置，主要用于本机恢复，不等于跨设备同步。费用账本独立保存，恢复历史工作空间不会清空累计费用，请不要手动删除账本。

在「工作产出」下载当前成果，或按委托授权交付到指定目录。向他人分享前核对文档里的业务内容。分享安装包只提供程序，对方使用自己的模型、来源权限和工作空间。

本说明可通过页首「下载说明」导出 Markdown，离线保存或随安装包分享。

## 常见问题与排查顺序

| 问题 | 先检查 |
| --- | --- |
| 点击推进后没有开始 | 模型角色是否配置；委托是否暂停；全局时段、调用次数、预算和依赖是否允许 |
| 材料进来了，却没有事项 | 队列是否完成；是否只选了保存；归类有无冲突；项目是否有启用的委托或规则 |
| 选中文字没有弹窗 | 选区开关和辅助功能权限；App 是否运行；是否有未提交草稿；编辑区拖选后是否出现兼容工具栏；读取失败可手动复制粘贴 |
| 截图为空或识别错误 | 系统权限、图片是否包含文字、分辨率及限制；关键字段手动核对 |
| 自动选模一直用同一个模型 | 是否启用并保存；两档是否同一配置；事项是否有固定偏好；逐次调用的选模原因 |
| 有模型记录却没有准确费用 | 是否返回 usage；是否配置价格；是否为旧记录或失败请求；展开调用详情查看缺口 |
| 找不到最终文稿 | 到工作产出先看当前成果；历史过程稿默认收起；尚未完成的步骤可能还没有当前稿 |
| 结果不符合要求 | 在原成果提出具体修改意见，写清删减、缺口和完成标准；查看原委托是否需要恢复 |
| DW 已挂载但没有被使用 | 当前委托是否勾选授权；版本是否变化；任务是否确实需要已支持的四项能力 |
| 来源无法同步 | 凭据是否过期、目标范围是否授权、目录是否存在、网络是否可用；查看连接错误后重试 |

仍不清楚时，先到「工作体检」查看配置与阻塞，再到委托运行记录或「运行与恢复」核对具体调用。保留错误、时间、模型与操作步骤，便于定位；反馈时不要附带密钥。

Agent 的工具与连接中另有「真实模型验收」：用配置模型运行 10 个样例，验证计划、依赖、跟进和恢复；会实际消耗模型额度，最多 300 次调用。文件使用独立临时目录，GitHub 与时间变化使用模拟环境。首次上手无需运行这项测试。


## 需要补充时如何选择方案

入口：**待我处理 → 待我决策**。

- Agent 会把阻碍推进的缺口整理成问题，说明为什么需要回答，尽量给出 2–3 个方案。每个方案说明适用情形和对推进的影响，其中一项标为「推荐」。
- 选择方案后，可以补充限制或预期，再点「保存决定并继续」。推荐项不会自动提交；需要提供日期、负责人或材料的方案必须填写具体内容。
- 始终提供「自行填写」。如果已有方案不适合，可直接写出你的处理方式。选择和补充会一起进入原事项的备注与决定历史，Agent 据此调整计划。
- 没有足够依据生成具体方案时，应用提供「补充关键信息」「先推进可确认的部分」等方式，不编造事实。选择先推进部分内容仍保留原完成标准，关键缺口仍需补齐。
- 问题或材料更新时，草稿保留，但需要核对最新依据；原选项内容变化后必须重新选择。已暂停的工作回答后仍暂停，累计费用和工具权限不因回答而重置。
- 权限问题提供「连接飞书并读取 / 补齐访问权限」「我提供所需材料」「稍后处理」，另有「自行填写」。选择提供材料时，把文字作为用户提供的来源交给原事项；自行填写可提出其他处理方案。这两种方式均不会授予访问权限，也不会把未读取的原文当作已验证。

## 权限问题与飞书文档授权

Agent 遇到登录、文档访问或工具授权问题时，会在「待我处理」生成「需要授权」卡片，说明访问范围和用途。请优先按卡片完成授权；在聊天中回复“同意”不等于账号已登录或文档已经可读。

### 独立事项读取飞书文档

1. 把飞书文档链接与要求写入事项。支持 `feishu.cn`、`larksuite.com`、`larkoffice.com` 的 `/docx/`、`/wiki/` 地址，不需要另建项目。
2. 在「待我处理」打开对应事项的授权卡片，选择「连接飞书并读取」，点击「允许读取并检查」。
3. 如缺少用户登录，点击「连接飞书并授权」，再点击「打开飞书授权页」。在网页中核对账号及卡片列出的接口权限并确认。
4. 完成网页授权后，App 自动验证文档能否读取；也可点击「已授权，检查并继续」。读取成功才会把正文加入原事项，沿用原进度和累计预算继续。暂停中的委托仍保持暂停，其他未决问题仍需处理。

只使用飞书用户身份，不会把机器人身份当作你的文档权限。接口申请 `docx:document:readonly`，知识库链接还申请 `wiki:node:read`。飞书 OAuth 权限作用于当前 CLI 应用及你的账号可访问范围；App 内仅允许此委托读取卡片指定文档。正文会交给此事项配置的模型服务处理。登录凭据由飞书 CLI 管理；App 不把设备码、授权链接或访问令牌存进事项或模型上下文。

### 不同失败如何处理

- **需要登录**：连接飞书，在官方授权页完成用户登录。浏览器或飞书客户端已登录不代表 CLI 已登录。
- **应用缺少接口权限**：请应用管理员在飞书开放平台开通卡片列出的只读权限，再连接飞书。组织限制需要管理员处理。
- **文档访问受限**：点击「打开原文申请访问」，核对使用的账号，并向文档所有者申请阅读权限。用户登录成功并不保证能读所有文档。
- **未安装或配置 CLI**：安装官方 `@larksuite/cli`，通过 `lark-cli config init` 完成应用配置后重新检查。
- **授权链接过期、重启或检查中断**：点击「重新连接飞书」生成新链接。历史进度和原额度保留。
- **其他平台或工具权限**：卡片提醒到对应平台或委托设置授权，处理后点「已处理权限，重新检查」。只有原工具实际读取成功后，Agent 才能把取得的内容作为证据；这不会自动授予其他平台权限。

等待授权不会调用模型。可选「稍后处理」，点击「保存并等待」保留事项。通用权限卡片负责提醒和恢复入口；目前内置直接 OAuth 流程为飞书文档，其他平台仍需在其原有授权入口完成。


## 继续推进与停止条件（v0.33）

未知用量不代表已经超出 $100。App 保留预留并在原上限内继续，费用区可随时核对已报告费用与预留金额；追加 $100 是另一项明确确认。

## 在飞书创建交付文档（v0.34.4）

## 持续推进与防止重复执行（v0.35.0）

在「Agent 委托」的「实际进展」查看最近有效进展、最近动作、当前阶段、待解决缺口和复用查询次数。一次调用成功只代表工具返回；新增证据、文稿变化、检查通过或交付成功才表示取得进展。

- **阶段接续**：计划中的文字步骤完成后，App 安排内容检查；实际交付后安排结果检查，再核对整体目标。已授权的创建与更新继续沿用原授权。
- **保持已有工作**：步骤或事项改标题不会重做已完成步骤。步骤修改保留未受影响的前序成果，记录本步输入依据、产出及回执。纯授权完成不会清空计划或稿件。
- **发现循环**：相同读取累计三次未带来新证据时，App 尝试转到未展开的边界或当前未完成步骤。交替读取、批次调序和拆分也会识别；重启和暂停后继续保留记录。
- **按缺口恢复**：缺口有独立记录。没有新增相关依据的同一缺口持续失败时，先切换修订策略并重新核对实际效果；确实无法通过现有工具补齐时才展示具体缺口，不自动降低验收标准。其他独立委托继续运行。
- **按需读取**：主稿、完整证据目录和当前要求优先进入模型上下文；历史稿保留，可按 ID 读取。节选不能作为某个事实不存在的证明。
- **费用连续累计**：查询复用、计划调整、恢复和重启不重置费用。每次推进全过程仍共用原额度；这不限制正常长任务的总调用轮数。

升级会导入旧查询、已有检查和缺口。只有旧检查依据仍有效时才沿用，不能靠迁移把未完成工作标成完成。界面中已存在的授权与预算条件继续生效。


## 可靠执行与恢复（0.36 起）

- 同一材料内容未变时，保留读取记录并复用证据。调用时间、重复引用和无效附加参数不会被算成新进展；仓库仍在每次调用前检查最新内容。
- 用户修改背景、目标或完成标准会形成独立修订。生成和检查期间要求发生变化时，旧结果保留为候选或弃用检查结论，按当前依据继续。
- 「实际进展」显示有效步骤、未解决缺口、内容未变化的读取次数，以及平台失败后的重试时间。网络或限流等待不要求用户确认费用；仍沿用该次推进的累计额度。
- 信息连接分页循环时停止该窗口，保留已收材料。点击「同步」重新扫描原窗口；更换凭据后从窗口起点核对新权限可见资料。

- 删除或恢复事项时只检查有关事项、委托、依赖和项目；无关工作继续执行。存在执行中或结果未知的关联外部动作时，需要先核对结果。
- 首次升级到状态格式 v2 会保留迁移前原文件。恢复旧备份保留当前要求、费用、授权撤销和外部回执，并重新核对已失效的确认。不要用旧版应用直接写入已升级的工作空间。

### 自动控制重复消耗

助手会优先使用已保存资料。读取长文档时由程序自动拼接页面，不需要每页都调用模型；已通过且要求、证据、权限和交付都未变化的检查可直接复用。修改要求或证据后会重新核验。

同一要求下，累计多次尝试未取得新证据或有效成果时，助手会自动切换推进方式：复用已有资料直接生成，针对检查缺口修改原稿，或改查尚未展开的证据边界。每种策略执行后都核对真实进展，失败的策略保留记录，重启不会重复尝试同一路径。次数阈值触发纠偏，不会直接暂停委托。

只有可用路径已经尝试且仍无新执行条件时，显示已尝试方法和具体阻塞；相关证据或权限变化后自动重新评估。需要授权、预算或人工信息时仍使用原有处理入口，不要求只确认“继续”。人工暂停保持有效，原累计费用上限不变。

## 原稿核验接续（0.41 起）

暂停自动托管时，已发出的请求可以返回并保存断点，随后不再启动新请求。恢复后，助手继续检查已保存的原稿；费用、已尝试方法和检查次数继续累计。重启应用不会把工作重新当作第一次执行。

如果旧版本在暂停途中错误提示“没有进展”，委托详情可能显示「继续未完成的原稿检查」。点击「继续原稿核验」后，助手会重新核对旧运行记录，接续原稿检查。这个操作不会修改你的范围、验收标准或费用上限。全局或单项暂停仍然有效，需要恢复运行后才会执行。只有原稿、请求记录和暂停经过足够明确时才提供此入口；若信息或状态已变化，刷新后按新的具体提示处理。

外部文档写入结果不明时，助手先核对原动作及原文档，不立即重复写入。成果通过内容检查、交付回读和结果检查后才进入待验收，最终是否接受仍由你决定。
