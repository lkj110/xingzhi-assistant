# Single protocol gate, with bounded private failure diagnostics

This is a new entrance. Historical runners, packs, the installed base and candidate product files stay frozen. It imports the sealed marker runner's phase, evidence, output and checkpoint guards; its seal binds those dependencies and the local host tool hashes.

Offline mode substitutes local Node processes for every model CLI execution. The matrix covers generation reading source before creating an artifact, verification reading before a verdict, old budget refusal, an additional read exceeding the budget, protocol rejection, unknown usage and malformed inner output. Synthetic token receipts prove accounting only, never model quality or expected cost.

Live mode is not authorized by this repository. A new explicit approval and single-use authorization must bind the reviewed runner, sample seal, unchanged CLI hash, plan and output directory. The proposed ceiling is 5 application attempts (4 forward slots plus 1 local refusal slot), with a 120,000 input+output token stop threshold and one fixed 45-minute window. In-flight usage may exceed the threshold. No retries, fallback, CLI discovery probes, business cases, expression confirmation or final acceptance are provided. Internal provider HTTP retries are not observable as application attempts.

Only already-exposed G01 is eligible. A pass establishes protocol recovery and an independently reviewed bound draft; it is not fresh business acceptance, human final acceptance, or evidence of hallucination/false-block/false-release rates. Six unused business cases remain sealed and unrun. A fourth required dispatch needs known prior usage plus its conservative reservation to fit the threshold; admission is not promised by approval.

Diagnostics retain timestamps, exit/signal, process-tree confirmation, a maximum of four whitelisted error events, failure category and authoritative-usage presence. Bounds: 32 KiB per stdout line, 8 KiB stderr, 2,048 characters per message, 24 KiB for the diagnostic object. Oversized content is omitted. Sensitive labelled suffixes, escaped sensitive structures, credentials in URLs and known request echoes are redacted before clipping. Unlabelled or novel secret formats cannot be guaranteed detectable: keep diagnostics private and publish only reviewed categories and hashes. Existing private request/output audits remain private. Diagnostics do not enter model input or create usage receipts.

The old provider rejection's root cause remains unknown. Synthetic HTTP 503 and failure messages are fault fixtures, not observations of the historical provider. Protocol rejection or unknown usage stops the round immediately; known usage before failure is retained and the unknown aggregate stays null. Content and evidence are re-bound after independent review so a stale approval cannot release a changed draft.

Run unit tests with `node --test evaluations/foundation-diagnostic-runner/*.test.cjs`. Seal with `node evaluations/foundation-diagnostic-runner/identity.cjs` before the reviewed preparation is finalized. Run `node evaluations/foundation-diagnostic-runner/integration.cjs --executable <isolated-candidate-exe> --output <new-dedicated-output>` for the bounded offline matrix. Once reviewed, do not reseal or reuse an old live authorization.
