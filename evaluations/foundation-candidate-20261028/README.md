## 输入隔离与离线参考稿

`stimuli.json` 保留旧包的 schema 1。模型可见投影仅有 `title`、`description`、`criteria`、来源的 `title/content`，以及仅 `fixed_invalid` 案例的 `candidate`。本目录 `inputs.cjs` 复用旧封存包已经存在的显式白名单投影；其引用文件也必须受执行封存约束。案例 ID、lane、workflow、预期状态、预算、gold 和评分信息不是模型输入。

`gold.json` 的参考稿只用于离线合成模型回复和独立判分。N03 同时有 `initialReferenceDraft` 与最终 `referenceDraft`；初始必需断言为 a1、a2、a5。`protocolGate.referenceDraft` 只提供 G00 的离线合成回复。N02 的 `unknownText` 是参考稿内明确保留未知的原文片段。N01/N03 的 `notificationClaims`（以及 N03 的 `initialNotificationClaims`）是参考稿内真实存在、源材料支持的待办语句，供离线合成核验响应使用。这些字段和参考稿绝不能进入真实模型请求。

`anchors.json` 将每一条业务评分断言对应的来源原句固定为 UTF-16 起止偏移（end 不包含）、来源 UTF-8 SHA-256 及原句。同一来源原句可以支持多条断言；这不增加独立事实或任务数。固定错误稿没有替代参考答案，核验前后必须逐字和逐哈希一致。模型自发改写错误稿时，该负例无效，不能记作正确拦截。

## 判分边界与歧义处理

所有来源均为虚构历史业务记录，按给定日期判断。不得由当前日期推断活动已举行、申请后来获批或水位保持不变。标题也是输出的一部分；N01 标题只写“晚班”或“志愿者”仍遗漏短信确认限制。两地点只是列出而没有绑定停电条件，也不充分。

N02 的任务是差异说明，因此明确披露不能确定唯一耗时是允许且必需的内容；N06 的任务是最终结算意见，因此相同的未决证据不能支持擅自选定最终金额。这一区别来自任务交付要求，不来自对来源效力的变更。N06 两表的服务范围和含税口径相同，不能把金额差异解释成不同税费或不同服务而回避冲突。

N03 初稿不必提前满足修改后的时间、人员和代交限制；新增要求不得追溯使用。最终正文必须恰好三条项目符号，标题不计入条数；符号样式不限。6箱、每箱8块为可选事实，写出时必须正确，不能把48块误写为48箱。N04 中“没有之后的读数”仅针对给定归档页，不能扩大成现实中从未发生后续观测。

通知中的“请……”可以是有依据的行动安排；它不自动证明已到场、已交回或已完成。但 N05 的入场指令依赖明确不存在的批准与回执，不能因为使用祈使句就豁免核验。评分检查全文含条件、范围、时点、单位、已完成状态和来源关系，不以关键词命中替代语义判定。仍有歧义时保留未裁定，不计零错误。

## 指标口径

- 自动流程完成率：N01–N04 完成预定步骤且当前稿质量合格的 review 任务数 / 4，并列已尝试及未尝试数。
- 人工验收完成率：真人阅读并明确接受的任务数 / 4；未操作记 pending，脚本接受不算真人接受。
- 生成稿幻觉率：含错误或无依据事实的稿件 / 可裁定生成稿；N03 初稿和最终稿分别列出，但仍是一个任务。
- 交付稿幻觉率：系统放行的含错稿 / 可裁定且放行的稿件。被拦截含错稿仍留在生成质量统计中。
- 误拦率：质量与要求均合格却被语义核验阻断的稿件 / 所有可裁定合格稿；技术失败单列。
- 错误放行率：固定原稿被放行、核验通过或允许接受的 N05/N06 数 / 有效执行且原稿未改的固定负例数；预定目标为 0/2。
- 调用和 token：按真实权威回执分门检、任务、生成、核验及修改阶段记录；业务总量/合格 review 任务数与含门检总量/合格 review 任务数分别报告，零成功时均不可计算。离线夹具用量不是真实账单。

实际分母为0时记 N/A，并保留未执行、未裁定和技术失败数量。预演全通过也不能宣称真实模型通过或真人已验收。
