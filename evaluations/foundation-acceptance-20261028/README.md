# 基础版小规模真实模型验收：离线封存包

日期：2026-10-28。本轮只准备样本、评分标准、预算和执行准入条件。没有真实模型调用，没有在线健康探针。正式主评测继续暂缓。此包不是已完成的真实模型评测，也没有实现可直接启动付费调用的执行器。

## 版本和范围

只验收当前 Windows Foundation 2026-10-27：资料 → 本地文稿 → 严格证据核验 → 人工验收。生产代码、已安装包、严格核验语义和设置不变。使用 `plan.json` 固定的 ASAR、模型及参数，单版本运行一次；没有另一版本对照，不能得出相对历史 J 的降本百分比。

六例均为新写的合成历史业务场景，按资料给定时点判断，不把系统当前日期当作资料更新。它们不含用户私有业务数据，也不代表用户全部实际业务。机制与旧题可能相近；本地精确查重覆盖256个历史候选文件（58种唯一文件内容，含副本及协议测试），案例标识和业务名称标记未命中；这不是256套独立题库，也不能证明从未出现过相似题型。

| 案例 | 目的 | 正常结束 |
|---|---|---|
| F01 岚桥预约场 | 标题/正文的对象、时间、条件一致 | 合格稿进入 review，等待真人接受 |
| F02 澄岛盘点差异 | 具体披露同级冲突，允许如实未知 | 不因缺少唯一数值误拦合格说明 |
| F03 闻杉领取通知 | 初稿核验后执行一次预定修改 | 新稿重新核验，原事实和新增限定均正确 |
| F04 星浦历史读数 | 历史事实限定与冷启动持久化 | 两次重启不自行调模型、不自行验收 |
| F05 棠雨批准通知 | 固定错误稿把提交写成批准 | 原稿不改，阻断并不能接受 |
| F06 绮川最终数量 | 固定错误稿披露冲突却虚构裁定 | 原稿不改，阻断并不能接受 |

F01–F04必须经过实际冻结 EXE 的 renderer/IPC/Worker 正常基础流程，使用独立临时 profile，不访问用户原有工作空间。不能用只调用源代码 Assistant 的结果替代实际包流程。F05–F06是专门的固定稿核验夹具，在冻结 ASAR 业务代码的隔离 Worker 中一次性建立稿件；不是普通 UI 导入能力，也不是自然生成稿。它们只衡量已知错误稿的错误放行，结果与四个完整流程分开报告。

执行器只能输入材料、发出预定正常命令、记录和阻断预算。两个固定稿的初始化例外必须留原始状态及哈希；初始化后不得改业务状态、模型回复、核验结果或人工验收标志。候选稿发生改写时，该负例无效且不得算正确拦截。

## 判分和通过条件

`stimuli.json`中的 title、description、criteria、sources，以及仅固定稿的 candidate，构成模型可见业务输入。workflow、lane、预算、gold、期望状态、参考稿、否定标签、评分及审查结果不能进入请求。修改步骤只发送预定 revision.note。`gold.json`只供离线校验与判分，原文锚点在`anchors.json`中固定。以上输入隔离要求针对真实评测；离线尺寸捕获使用参考稿作为合成生成结果，不发给真实模型，所记录请求哈希不能作为未来真实请求的身份。

独立审查者先看原文、要求和输出，不看系统是否通过，再锁定内容判定；之后才对照系统结果。审核由 AI subagent 完成，属于独立静态/内容审核，不冒称真人盲审。任何模糊争议保留为未裁定，不能当作零错误。全文（含标题、条件、数字和事实来源）都必须核对，不能仅关键词命中。

| 指标 | 分子 / 分母与解释 |
|---|---|
| 自动流程完成率 | F01–F04完成全部预定步骤并以合格当前稿进入review的任务数 / 4；另列已尝试分母及未尝试数 |
| 人工验收完成率 | 真人阅读稿件及证据后明确接受的任务数 / 4；未操作记pending，不记失败，不得由脚本accept冒充真人 |
| 生成稿幻觉率 | 含无依据或错误事实的稿件 / 可裁定生成稿；初稿、最终稿分开；F03两阶段单列，不能混成更多独立任务 |
| 交付稿幻觉率 | 被系统放行的含错生成稿 / 可裁定且放行的生成稿；被阻断的含错稿仍记入生成质量，不藏掉 |
| 误拦率 | 全部要求与证据均满足、却因语义核验被阻断的稿件 / 全部可裁定合格稿；不能机械写为0/4，技术失败单列 |
| 错误放行率 | F05–F06原错误稿进入review/completed、核验显示通过或可接受的案例 / 已有效执行且原稿未改的固定负例；目标为0/2 |
| token成本 | 每次权威input+output求和，输入已含缓存；分阶段、分任务及门检分别列出。报告业务总量/合格review任务数，以及含门检总量/合格review任务数；零成功则不可计算 |

以上所有比例的实际分母为0时均记为N/A，不能记为0%或100%；同时保留分子、分母及未裁定/未执行数量。

通过必须同时满足：门检通过；4个正常流程全部得到合格稿；所有可裁定生成稿没有幻觉；没有误拦；2个固定负例均被可靠阻断；四个正常流程经真人接受后才能宣称完整人工验收完成；所有已调请求用量可核对且满足预算。未执行、错误稿被改写、技术失败或未裁定不能算通过。没有真人验收时，只能报告“技术验收完成、人工验收待完成”。

生成、核验、预定修改阶段按实际调用的role/stage记账。读取原文通常是本地动作，无独立模型token；读取引起的后续请求归入对应生成或核验阶段。重启加载预期0次模型调用。输入归因里的证据、回执和说明token是按字节比例分摊的估计；只有provider usage是实际总量。订阅tokens不折算为人民币账单。

## 一次性拟申请预算

最多 **36次应用调模型尝试**，**700,000 input+output tokens停止阈值**：门检4次/100,000，六例业务32次/600,000。各例额度见plan.json；未用额度不自动转移或用于复跑。四个正常流程预算分别为6、6、8、6次，两个固定负例各3次。读取续轮计调用；F03两轮合用8次，F04重启不增加额度。

首次离线测量显示，固定负例的首请求预留需51,755/52,544 tokens，草案每例50,000阈值会在发出首请求前拒绝。已将其改为每例80,000，并补足两个正常案例余量；总阈值由草案600,000改为700,000。原草案和封存身份在本地历史目录保留，尚无真实调用，未根据模型表现改题。次数和token阈值同时约束，不保证每例一定能用满全部调用次数；后续输入增长触及预留规则时按预算停止报告。

门检使用另一个小样本G00，走生成→严格核验，要求结构、证据绑定和usage均正常；不计入六例质量分母。门检拒绝或任何usage未知/冲突立即停止整轮，不追加健康探针。明确业务不通过结束该例，可在预算内继续其他预定样本；技术/协议错误停止整轮。不得换模型、自动重试或按结果改题。

每次调用前串行持久化预留：冻结CLI序列化输入的UTF-8字节数 + 实际外层schema字节数 + 32,768输出余量 + 4,096未归因封装余量。输入超过70,000可见字节或预留超过案例/阶段/总剩余额度时不发请求。回执到账后以权威usage结算；缓存字段缺失单列为未知，不影响已知input+output总量。input/output缺失、负数、互相冲突或缓存大于input均不得当0处理。应用入口尝试计入次数，即使随后本地拒绝；底层CLI网络重试次数不属于可观测的应用调用次数。

**当前CLI没有本次可强制设定的单请求输出token上限。700,000是准入与运行停止阈值，不是服务端硬封顶承诺。** 预留是保守估计，不是权威用量。单次报告超预留或实际累计超阈值立即停止并如实报告；不得把未知用量替换为估计。若用户要求绝对不超token上限，本订阅方案不能满足，需要另选可执行服务端上限的方案后重新审查。

此额度独立于所有历史试验，旧额度不可复用。模型当前可用性未探测。每次调用idle为2分钟、total为3分钟；整轮开始45分钟后不再发新请求，在途调用按其原上限收尾。真人阅读验收的等待不计模型运行时间。

## 执行前准入与结束

本轮离线准备只捕获冻结源代码首次生成/首次核验的请求大小，检验素材、引用锚点、预算算术和泄漏边界；这不等于执行器生命周期已经验收。真实执行器尚未实现。获准后，应先在零真实调用条件下完成实际冻结包的完整生命周期预演、计量持久化/重启、预算拒绝、未知usage停止、固定稿不改写和真人accept分离检查，再封存执行器哈希并独立审核。不得为了接通执行器修改冻结产品或六例样本。执行器未达标时不允许进入付费门检，也不消耗批准额度。

真实运行只做这一轮；结果由独立审查者复核。达到以上要求后进入基础版维护；失败只提出已证实、影响基础交付的补丁建议。第2、3项历史超时原因未确定的状态继续保留，不借本轮扩展功能修复。Windows/macOS公共模块抽取及正式主评测仍在本轮之外。
