# 全新人工表达确认验收样本（准备中）

本目录由独立样本作者在产品提交0d448e264c87a6e65638b330141408335c33c6c1冻结后离线编写。全部业务资料为合成数据；作者阅读旧格式和失败教训，但没有把旧业务材料改名，也没有修改产品、旧封存或runner。此处没有真实授权；独立审查与封存状态由主agent维护，不能据本样本目录启动live。

顺序固定为G01门检、F01样张批准范围负例、F02版本号裁定负例、F03声景复听通知、F04同视角箭头冲突说明、F05目录补录初终稿、F06历史队列快照重启。预算拟议40次应用尝试、800000 input+output tokens停止阈值，分配及停止规则以plan.json为准。两固定错误稿保持原字节，不能修稿救分。

inputs.cjs是完整初始业务输入白名单：只给title、历史前缀+description、criteria、sources的title/content；固定负例另给candidate。revision.note仅在预定修改时单独输入；revision.additionalCriteria只作评分索引，不制造新义务。gold、断言、要求覆盖、预算、lane、workflow和canary均禁止进入live模型上下文。notificationClaims仅供离线替身，不要求真实模型选择proposal，更不能为触发等待而改真实kind。

requirements.json从完整title/description/criteria/历史前缀/revision.note/流程提取；它是作者清单，非独立盲审。coverage.json的逐字span只作定位，不代替逐条含义判断；作者同时提供120条要求、2条许可、128个阶段绑定（59文本覆盖、7负例预期违例、62流程未执行）。F05初稿不受终稿两段及新增字段规则追溯约束，真实额外信息可出现。F04允许准确朝向未知。八个参考/固定稿版本均须由独立审核者从完整输入和来源反查；局部覆盖不使负例合格。

成功标准须区分：生成内容合格、系统核验通过、表达待人工确认、真人验收完成。等待不是通过。正例的最终成功状态必须为completed并有真实用户最终验收；review仅为验收前状态，marker_confirmation仅为允许的中间态，pendingCountsAsPass固定为false。每个预定稿阶段最多一次真人表达确认及一次随后显式重检；初稿与修改稿各为一个阶段。runner不能代确认或验收。45分钟发起窗口不因等待人而重置；未知用量、协议拒绝、传输/超时、任一级预算拒绝或触发、非计划调用、身份变化、错误放行或首次案例失败均停整轮。到期未答为pending，不能默认同意。

若没有自然触发marker，真实人工分支记未触发/未验证；不得改稿、改kind或追加题。新样本只允许离线执行器准备与独立审查；若为了这些样本修改产品，应降为回归材料。freshness.json说明与旧题的业务维度区别，不把题型相似本身当新颖性证明。

此目录暂不包含真实授权或伪造审查通过记录。package-manifest由主agent提供并绑定实际独立候选包；最终seal与preflight应在另一审核者确认后生成。
